# ADR 0001: rack 채널 카드의 이어 스텐실만 작은 활자로 찍는다

- 상태: 채택
- 날짜: 2026-09-25
- 결정한 사람: 메인테이너
- 관련: 감사 #348 E3/TD-60(px 글꼴 +1px), `docs/skins/rack.md`의 카드(행) chrome 절

## 배경

rack 스킨은 카드 왼쪽 랙 이어에 카드 종류를 세로 스텐실로 찍는다(9px 굵은 대문자,
자간 1.5px). #300이 활자 체계를 한 단계 키울 때 C++ 페인터의 `setPixelSize` 값들은
빠졌고, 감사 #348 E3에 따라 그 89곳을 1px씩 키웠다. 이어 스텐실도 그중 하나다.

채널 카드는 이어 스텐실이 나오는 카드 가운데 가장 낮다(판 높이 약 96px). 스텐실이
쓸 수 있는 길이는 아래 나사와 위 SELECT LED 사이로, 이번에 실제 부품 위치에 맞춰
다시 잰 뒤에도 약 43px다. CHANNEL은 9px·자간 1.5px에서 약 53px, 자간을 없애도 약
43px가 들어 들어가지 않는다. 키우기 전에도 이미 CHAN까지만 보이고 잘려 있었다.

## 검토한 방안

1. 채널 카드에서만 스텐실을 뺀다. 잘린 글자는 사라지지만 카드 종류 표시도 사라진다.
2. CH 같은 짧은 표기를 쓴다. rack.md에 없는 새 표기를 만들게 된다.
3. 채널 카드를 약 10px 키운다. 장식 하나 때문에 목록 전체의 밀도가 줄어든다.
4. 채널 카드의 스텐실만 작은 활자로 찍는다.

## 결정

4번을 택한다. 채널 카드의 이어 스텐실은 E3 이전 크기(8px)에서 시작해, 단어 전체가
들어갈 때까지 1px씩 줄이고(하한 5px), 그래도 안 되면 자간을 0.5px씩 줄인다(하한 0).
지금 판 높이에서는 6px·자간 1.5px로 CHANNEL 전체가 찍힌다. 다른 카드의 스텐실은 E3
크기(9px·자간 1.5px)를 그대로 쓰고, 단어가 들어가지 않으면 찍지 않는다. 어느
경우에도 글자를 잘라 찍지 않는다.

메인테이너 판단은 이 스텐실이 사용자에게 중요한 정보가 아니라는 데 있다. 카드 종류는
헤더의 이름표가 이미 말하므로, 이어 스텐실은 온전히 보이기만 하면 작아도 된다.

## 결과

- 채널 카드의 스텐실이 처음으로 잘리지 않고 CHANNEL 전체를 보인다. 대신 다른 카드의
  스텐실보다 작다.
- 이 규칙은 `RackSkin.CommandRows.cpp`의 `paintCardChrome` 이어 블록에서 채널 카드에만
  걸려 있다. 다른 카드에 같은 문제가 생기면 이 ADR을 근거로 삼지 말고 따로 판정한다.
- 같은 라운드에서 거부된 VST 버스의 상태 줄은 크기를 되돌리지 않고 자리를 넓혀
  해결했다(유닛 줄 아래 한 줄을 따로 쓰고, 길면 줄바꿈한다).
