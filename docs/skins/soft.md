# Soft Lab (`soft`) — 디자인 헌법

> **두려울 수 없는 설정 화면.** iPhone 설정 / macOS System Settings의 평온함.
> 둥글고, 넉넉하고, 만만하다.

## 철학

Soft Lab은 오디오 도구가 아니라 **소비자용 설정 앱**처럼 보이기를 선택한
스킨이다. 다른 네 스킨이 "프로의 장비"를 연기할 때, soft는 "겁먹은 초보자도
망칠 수 없는 화면"을 연기한다. 그래서 이 스킨의 모든 결정은 한 질문으로
환원된다: *이 요소가 화면을 더 불안하게 만드는가, 더 평온하게 만드는가?*

공식 타이브레이커는 "**의심스러우면 요소를 빼고 여백을 넣어라**"이다. 이
원칙의 가장 유명한 적용이 raw 미리보기 스트립 제거다: 카드마다 깔리는 모노
설정 원문은 "화면을 불안하게 만드는 바로 그런 요소"라서 이 스킨만
`showRawPreview = false`로 끈다(원문은 `...` 편집 버튼으로 여전히 닿는다 —
숨기는 것은 표현이지 기능이 아니다).

그림자에 대한 입장이 이 스킨의 헌법 중 가장 자주 인용된다: **그림자 이펙트는
절대 쓰지 않고, "두 단계의 배경 명도 스텝 + 아주 옅은 1px 보더"로 고도를
위조한다.** 픽커 라운드의 에이전트는 이것을 "the constitutional Soft way"라고
불렀다. 파스텔 색이 필요할 때도 새 팔레트를 들이지 않고 토큰끼리 섞는다
(`softMix(accent, card, 0.30)` 같은 식) — 그래야 다크/라이트 양쪽에서 같은
규칙이 같은 평온함을 만든다.

## 불변 규칙

1. **그림자 금지, 고도는 명도 2스텝.** 면 아래에 한 스텝 어두운 받침을 깔고,
   면은 한 스텝 밝게 + 아주 옅은 1px 보더. 이게 이 스킨의 "그림자"다.
2. **호버는 정확히 한 스텝 상승.** 카드도, 노브 면도, 픽커 행도 같은 규칙.
3. **라운드 10~12px, 스타디움 우선.** 카드 12px. 작은 요소(배지, 검색창,
   하이라이트)는 완전한 알약(스타디움) 형태로 굴린다.
4. **위계는 크기와 여백.** 다섯 스킨 중 가장 큰 행(48px), 가장 넓은 들여쓰기.
   밀도로 위계를 만들지 않는다. 섹션 구분도 여백이 우선이다.
5. **파스텔은 토큰 혼합으로.** 새 색을 추가하지 말고 `softMix`/`softAlpha`로
   기존 토큰을 섞는다.
6. **모든 명령 타입이 같은 실루엣.** 타입 구분은 색 타일과 본문 형태로 하고,
   카드 외형은 하나로 평온하게 유지한다.

## 빛과 상태의 문법

- **hover** — 카드가 한 고도 스텝 떠오른다(`card → cardHover`). 노브는 면 색
  상승 + 인디케이터 점이 0.5px 자란다.
- **selected** — `cardSelected` + 액센트 보더. 픽커에서는 선택 틴트의
  스타디움 하이라이트 + 부드러운 액센트 외곽선.
- **focused** — 단단한 링이 아니라 **조용한 할로**(α 90, 3px)다.
- **dragging** — 인디케이터 점이 1px 자란다. "잡혀 있음"을 알리는 가장 차분한
  신호("the calmest possible 'I am held' cue").
- **disabled** — "잠자는 슬롯". 창 배경 속으로 가라앉아 점선 윤곽만 남는다.
  **빈 슬롯이지 경보가 아니다.** 경고색·강조 금지.

## 색의 의미론

다크는 따뜻한 네이비(#171923 배경, #282D3E 카드), 라이트는 따뜻한 크림
(#F7F4EF 배경, 보더 #E9DED1 — 차가운 회색이 아니라 베이지 계열)이다. 액센트는
#3B82F6 하나. 바이폴라 노브의 컷 쪽만 accent2를 쓰며, 그것도 카드 색으로 30%
섞은 파스텔로 누그러뜨린다. 채널 배지는 SoftPill, 채널 그룹은 SoftShadow
스타일이다.

## 타이포그래피

DM Sans. 다섯 스킨 중 유일하게 **두 줄 행이 헌법에 부합**한다(이름 + 흐린
설명 캡션) — 여백이 충분해서 두 줄이 빽빽함이 아니라 친절함으로 읽히기
때문이다. 캡션은 모노가 아닌 본문 서체의 흐린 색으로 쓴다(모노 원문 노출은
이 스킨의 금기와 충돌).

## 구성 요소별 표현

### 노브 — "더듬을 수 없는 손잡이" (Annex K)

다섯 스킨 중 **가장 큰** 노브다(인셋 4px뿐).

- 몸통: 2스텝 고도(받침 디스크 한 스텝 아래 + 면 한 스텝 위 + 옅은 1px 보더).
- 범위 호는 항상 보이는 파스텔 트랙, 값 호는 액센트를 카드 쪽으로 30% 섞은
  파스텔. **바이폴라는 12시 디텐트에서 자란다** — 부스트는 오른쪽 액센트,
  컷은 왼쪽 accent2. 유니폴라는 최소점에서 자라 한눈에 구분된다.
- 12시의 디텐트는 "부드러운 노치"(둥근 짧은 틱)다. 바이폴라(0dB 의미)에만.
- 인디케이터는 날카로운 선이 아니라 **둥근 점**이고, 호버/드래그에 살짝
  자란다.
- 값은 손잡이 **아래의 둥근 배지**(스타디움)에 담는다. 레거시 승격 다이얼은
  배지 없이 전체 높이를 손잡이에 쓴다.

### 카드(행) chrome

한 가지 평온한 실루엣. 헤더 스트립 없음(맥OS 설정 행에는 띠 제목이 없다) —
헤더는 카드 면을 공유하고, 내부 위계는 타입 타일·제목 크기·여백이 만든다.

### Copy 라우팅 — 수식 블록 (BlockChip)

각 출력이 하나의 둥근 "수식 블록"이다: `VSL = 0.86·L − 0.5·R`을 친근한 채널
칩과 계수 칩으로 조립한다. 블록은 액센트 가장자리의 둥근 카드이고, 왼쪽에
대상 채널 색의 둥근 막대가 붙는다. 행 끝의 점선 둥근 `[+]` 칩이 소스 추가
메뉴를 연다(장치 채널이 블록으로 시딩된다). 계수를 비우면 그 칩이 빠진다.

### 필터 픽커 — 둥근 설정 메뉴

소비자 설정 앱의 메뉴 카드 그 자체가 목표였다.

- 스타디움 알약 검색창.
- 48px **두 줄 행**: 템플릿 이름 + 흐린 설정 줄 캡션(비모노).
- 항목마다 iOS 설정풍 **둥근 사각 색 타일**에 이니셜 한 글자.
- 카테고리 헤더는 같은 파스텔로 틴트된 알약. 파스텔 색상은 카탈로그 순서로
  카테고리에 배정된다(순서가 바뀌면 색이 바뀌는 건 의도된 코스메틱 트레이드).
- 섹션 구분 장치는 **알약 위의 여백뿐**이다.
- 호버는 한 스텝 상승, 현재 행은 스타디움 하이라이트.

## 하지 말 것

- 그림자/블러 이펙트. 고도는 언제나 명도 2스텝으로 위조한다.
- 모노스페이스 원문(설정 줄)을 본문에 노출하기. raw 미리보기를 다시 켜는
  것은 헌법 개정 사안이다.
- 날카로운 모서리, 가는 헤어라인 격자, 빽빽한 표. (matrix/minimal의 어휘다)
- 비활성·오류 상태에 경고색을 입혀 "알람"으로 만들기.
- 새 파스텔 팔레트 추가. softMix로 만든다.
- 여백을 줄여 정보를 더 넣기. 의심스러우면 빼고 여백을 넣는다.

## 이웃 스킨과의 경계

가장 가까운 이웃은 **studio**다(둘 다 표준 카드 실루엣). 경계는 studio 헌법
문서의 경계 절과 동일하다: 라운드 8 vs 12, 고도 전략(알파 유리+반사광 vs
명도 2스텝), 노브(발광 호 vs 큰 몸통 손잡이), raw 미리보기(유지 vs 제거).
soft가 빛·글로우·반사 어휘를 집어 들면 studio를 침범한 것이다. soft의 빛은
"떠오름"(고도)이지 "발광"(광원)이 아니다.

## 새 요소를 이 스킨답게 만드는 법

1. 이 요소가 화면을 불안하게 하는가? 그렇다면 빼거나 여백으로 대체한다.
2. 면이 떠 있어야 하면 명도 2스텝 + 옅은 1px 보더로 고도를 만든다.
3. 라운드는 카드 12px, 소품은 스타디움. 직각이 보이면 잘못된 것이다.
4. 터치 타깃이 넉넉한가? (행 48px 기준에 어울리는 크기인가)
5. 파스텔이 필요하면 softMix로 토큰을 섞었는가?
6. 비활성 상태가 "잠자는 슬롯"(점선, 가라앉음)으로 표현되는가?
