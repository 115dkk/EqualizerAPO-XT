# Precision Minimal (`minimal`) — 디자인 헌법

> **은행 창구의 단말기.** Ableton 풍의 모노스페이스 터미널. 활자, 헤어라인,
> 정렬 — 그 셋이 전부이고, 그 셋으로 충분하다.

역사적 사정으로 QSS 파일명은 `precision_*.qss`를 유지한다(스킨 id는
`minimal`). 파일명을 맞추려고 리네임하지 않는다 — 의도된 보존이다.

## 철학

Precision Minimal은 "장식이 없을 때 정보가 가장 정확하다"는 학술적·공학적
절제의 스킨이다. 화면은 문서이고, 행은 문장이며, 상태는 잉크의 농도다. 이
스킨이 사용자에게 주는 약속은 단 하나다: **화면에 있는 모든 픽셀은 정보다.**
글리프는 의미를 운반하고, 선은 구획을 나누며, 명도 단계는 상태를 표시한다.
그 이상은 없다.

이 스킨의 멋은 금욕에서 온다. 다섯 스킨 중 가장 밀도가 높고(행 32px), 가장
색이 적고(무채색 회색 + 액센트 파랑 하나), 가장 키보드 친화적이다. 픽커
라운드에서 이 철학은 "번호식 터미널 인덱스"로 결정화됐다: 항목마다 0패딩
번호가 붙고, 숫자를 치면 그 번호로 점프하며, 선택은 전경/배경을 맞바꾼
**반전 블록**이다 — "텍스트 계기가 가질 수 있는 가장 무딘(blunt) 커서".

## 불변 규칙

1. **라운드 0.** 어디에도 곡률을 주지 않는다. 포커스 표시조차 정사각
   헤어라인 프레임이다.
2. **1px 헤어라인.** 모든 선은 1px다. 두꺼운 보더, 색 레일, 그림자 금지.
3. **상태 = 배경 명도 스텝.** 호버는 휴지에서 **정확히 한 스텝** 위
   (`card → cardHover`), 비활성은 휴지보다 **한 스텝 아래**(`surface`),
   선택은 액센트 계열의 명도 스텝(`cardSelected`)이다. 상태를 색상 변화나
   장식으로 말하지 않는다.
4. **모노스페이스가 UI 서체다.** `fontFamily`와 `monoFontFamily` 둘 다
   DM Mono. 위계는 글자 크기가 아니라 **밝기**로 만든다(mono 크기 하나).
5. **글리프는 정보, 색은 태그.** 행머리의 ASCII 글리프(`~` 필터, `>>`
   Include, `[]` VST, `->` Copy, `#` 주석)는 "이 줄이 어떤 종류인가"라는
   형태 정보다. 미지정 명령은 의미 없는 가운뎃점(`·`)으로 칸만 지킨다.
   배지는 OutlineOnly(외곽선만)로, 채움색을 주지 않는다.
6. **소스는 ASCII.** MSVC에 /utf-8을 걸지 않으므로 코드 안의 글리프는 순수
   ASCII이거나 `QChar(0x00B7)`처럼 코드포인트로 만든다. DM Mono에 없는
   글리프(예: U+25B8)는 오프스크린에서 두부(tofu)가 된다 — 화살이 필요하면
   `>`를 쓴다.
7. **액센트는 활성 중에만.** 평소엔 무채색이고, 드래그/입력 중인 컨트롤만
   액센트(#3B82F6)를 입는다.

## 빛과 상태의 문법

- **hover** — 배경 한 스텝 상승. 그게 전부다.
- **selected** — `cardSelected`(#1f3554 / #E8F1FF) 명도 스텝 + 액센트 보더.
  픽커에서는 반전 블록(전경/배경 스왑).
- **focused** — 정사각 1px 헤어라인 프레임.
- **dragging/armed** — 그 컨트롤의 잉크가 액센트로 바뀐다(인디케이터 선,
  판독 수치).
- **disabled** — 행머리에 `#`(설정 파일이 실제로 갖게 되는 주석 마커 —
  장식이 아니라 정보다)을 달고 배경이 한 스텝 가라앉는다.
- zebraStripe가 켜져 있다: 줄무늬는 표(table)를 읽는 보조선이다.

## 타이포그래피

DM Mono 단일. 캡션은 대문자 + 자간(letter-spacing)으로 구분한다. 강조가
필요하면 굵기(Bold)나 밝기를 올리지, 크기를 키우지 않는다. 숫자 칼럼은
0패딩으로 폭을 고정한다.

## 구성 요소별 표현

### 노브 — "숫자가 곧 컨트롤, 노브는 확인" (Annex K, AR1 N2 개정)

항상 보이는 모노 수치가 **주인공**이다. 행 다이얼처럼 수치를 위젯이 직접
들지 않는 경우(valueText 없음) 그 수치는 옆의 ValueScrubBox가 든다(아래
'파라미터 줄' 참조). 노브 자체는 채움 원반과 허브를 버리고 **헤어라인
계기**로 축소됐다: 1px 270° 범위 호, 잉크로 채운 1px 주행 호, 값 각도의
1px 방사 커서 틱이 전부다.

- **유니폴라**: 주행 호가 범위 시작(7시 30분)에서 값까지 차오른다. 틱·중심
  기점 없음.
- **바이폴라**: 12시에 고정 디텐트 틱(보조 잉크) + 디텐트에서 잰 1px 편차
  호(부스트 시계방향, 컷 반시계). 0 dB에서는 편차가 사라지고 틱만 남는다 —
  "디텐트 위의 커서, 편차 없음"이 정직한 0 dB이고, 두 종류는 한눈에 갈린다.
- 드래그 중에만 주행 잉크가 액센트가 된다. 평소엔 무채색.
- 수치를 직접 그리는 다이얼(valueText 있음)의 숫자는 본문 잉크보다 한 단계
  밝은 잉크(다크=흰색, 라이트=검정)다. 좁은 위젯에서 긴 값("-100.0")을
  만나면 **잘라내지 않고 폰트를 줄인다**.
- 레거시 승격 다이얼(valueText 없음): 호버/드래그 중에 ratio 유래 `NN%`를
  보여 준다 — "로그 스케일 다이얼에 대한 유일하게 정직한 판독값은
  퍼센트다".

### 파라미터 줄 — 잉크 사다리 (AR1 N2/X5)

BiQuad 행의 파라미터 영역은 세 단계 잉크 사다리로 읽힌다.

- **수치(ValueScrubBox, `valueScrub=true`)가 가장 밝다**: 다크=흰색,
  라이트=검정, 굵은 모노. 휴지에서는 입력 상자 chrome 없이 스트립에 바로
  인쇄된 숫자다. 호버는 정확히 한 배경 명도 스텝(스크럽 가능하다는 정직한
  신호), 편집 중에만 액센트 헤어라인 + 입력 그라운드가 켜진다.
- **선택기(콤보, `paramSelector`/`filterSelector`)는 캐럿을 단 캡션이다**:
  투명 배경 + 1px 밑줄 + 항상 보이는 본문 잉크 캐럿(▾ 모양의 보더 삼각형).
  상자가 아니므로 라벨로 오독되지 않고, 캐럿이 "바꿀 수 있는 토큰"임을
  말한다. 이름 콤보(filterSelector)는 행의 명령어라서 본문 잉크, 파라미터
  콤보(paramSelector)는 보조 잉크다. 호버는 한 명도 스텝, 액센트는 열림/
  포커스 중에만 밑줄과 캐럿에 들어온다.
- **순수 캡션(QLabel, 예: "Gain")은 보조 잉크다**. 정보의 중요도 = 잉크의
  밝기라는 원칙의 행 단위 적용이다.

### 카드(행) chrome

명령 하나 = 평평한 한 줄. 1px 헤어라인 박스, 직각, 헤더 판 없음(헤더는
투명 — 행이 한 줄의 텍스트로 읽혀야 하므로). `prepareCommandRow`가 행머리에
글리프 라벨(`MinimalTypeGlyph`, 최소 폭 18px)을 끼운다.

### Copy 라우팅 — 번호 스텝 리스트 (StepList)

`# │ DEST ← SOURCES` 형식의 모노 행. 명시적 `+`/`−` 부호, `×N` 계수 칩,
`INV` 마커. "학술적이고 모호하지 않은 텍스트+숫자 형태"가 설계 의도다.
장치 채널이 행으로 시딩되고, 행 끝의 대괄호풍 `[+]` 타깃이 소스 추가 메뉴를
연다. 계수 칩을 비우면 그 소스가 빠진다.

### 필터 픽커 — 번호식 터미널 인덱스

- 맨 위: 액센트 `>` 프롬프트 한 줄 + 우측의 실시간 매치 카운터(`22/22`).
- 섹션: 대문자·자간 캡션이 전폭 1px 룰 위에 앉는다. 같은 카테고리가 뒤에서
  다시 나타나도 캡션은 첫 등장 위치 하나로 합친다(중복 캡션은 "손상된
  출력"처럼 보인다).
- 항목: 0패딩 번호 칼럼 + 한 줄 모노 텍스트.
- **번호 규칙 (AR1 N3 개정): 번호는 페이지 좌표다.** setEntries 시점에
  휴지(전체) 색인의 표시 순서 — 첫 등장 순서로 합쳐진 섹션, 섹션 안은 원본
  순서 — 를 따라 1..NN을 한 번 매긴다. 그래서 전체 목록은 페이지를 따라
  곧게 내려가며 세고, 섹션을 가로질러 번호가 뒤섞이지 않는다. 매긴 뒤에는
  불변이다: 필터링은 줄을 숨길 뿐 인쇄된 번호를 바꾸지 않으므로, `07`은
  언제나 같은 템플릿으로 점프한다.
- 키보드: 문자는 필터, **순수 숫자는 번호 점프**(BIOS식), ↑↓/PgUp/PgDn 이동,
  Return 삽입. 맨 아래의 man-page식 키 범례 푸터가 이 문법 전체를 명시한다
  (`A-Z FILTER · NN JUMP · ↑↓ MOVE · RET INSERT`). 행 쪽에는 범례를 두지
  않는다 — 절제 우선.
- 아무것도 맞지 않는 질의에는 본문에 보조 잉크의 `NO MATCH` 한 줄로 답하고
  카운터가 `0/NN`을 읽는다. 터미널은 빈 결과를 보고하지, 연출하지 않는다.
- 다크는 어두운 콘솔의 밝은 글자, 라이트는 종이 위 인쇄물의 검은 블록 —
  같은 계기의 두 출력 매체다.
- 알려진 트레이드오프: 숫자만으로는 텍스트 검색이 안 된다(점프 예약).
  문자+숫자 혼합 질의는 정상 필터링된다.

### 참조 카드 — 터미널 한 줄 (AR2)

Include/Convolution/MultiConvolution/VST 행의 본문은 문자 그대로 **한 줄**이다
(`MinimalReferenceCardView`). 페이로드(파일/플러그인 이름)가 가장 밝은
잉크이고, 위치·IR 판독값(`100.0 ms  4800 samples  48000 Hz`)이 보조 잉크로
같은 줄에 이어지며, 상태조차 `!`(warning)/`!!`(critical) 잉크 태그로 줄에
접힌다. 결손은 전경/배경을 맞바꾼 반전 블록 `MISSING` — 텍스트 계기의 가장
무딘 커서다. 액션은 줄 끝의 대문자 모노 텍스트 명령(`BROWSE`/`LOCATE`/
`EDIT`/`IMPORT`/`PANEL`/`OPT`, 미번역 각인 문법)이고, 아이콘·필·둥근 배지는
없다. VST2/VST3와 ABS는 맨몸 모노 토큰이다. 멀티컨볼루션의 출력 채널
콤보는 줄머리에서 '캐럿을 단 캡션'(X5 선택기 문법)으로 앉는다.
"정보의 중요도 = 잉크의 밝기" 원칙의 행 단위 적용이다.

## 하지 말 것

- 곡률, 그림자, 글로우, 그라데이션. 하나라도 들어가면 이 스킨이 아니다.
- 상태를 새 색으로 표현하기. 명도 스텝 사다리(아래=비활성, 위=호버)를 깨지
  않는다.
- 글리프를 장식으로 추가하기. 글리프는 의미가 있을 때만 존재한다(가운뎃점은
  "의미 없음을 뜻하는 자리 지킴"이라는 의미다).
- 두 가지 폰트 크기로 위계 만들기. 밝기로 해결한다.
- 비-ASCII 글리프를 소스에 직접 넣기.
- 키보드 동선을 끊는 컨트롤(마우스 전용 UI) 추가.

## 이웃 스킨과의 경계

혼동 위험이 가장 큰 이웃은 **matrix**다 — 둘 다 모노스페이스, 1px 룰, 라운드
0을 쓴다. 경계는 은유에 있다: minimal은 **문서/터미널**(텍스트의 줄, 줄무늬,
무채색, 상태=잉크 농도)이고 matrix는 **계기판**(격자 텍스처, 좌표, 신호등
상태색, LED·램프, 상태=점등)이다. minimal에 격자 텍스처·상태색 램프·좌표가
들어오기 시작하면 matrix를 침범한 것이고, matrix가 줄무늬 텍스트 리스트로
변하면 minimal을 침범한 것이다.

## 새 요소를 이 스킨답게 만드는 법

1. 텍스트 한 줄로 표현할 수 있는가? 있다면 그렇게 한다.
2. 모든 선이 1px이고 모든 모서리가 직각인가?
3. 상태가 명도 스텝 사다리에만 의존하는가? (새 색을 도입하지 않았는가)
4. 키보드만으로 완결되는가? 키 문법이 화면 어딘가에 적혀 있는가?
5. 번호·정렬·자간이 정보를 운반하는가, 장식인가?
6. 다크=콘솔, 라이트=인쇄물로 둘 다 자연스러운가?
