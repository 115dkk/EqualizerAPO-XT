# Hardware Rack (`rack`) — 디자인 헌법

> **앰프 페이스플레이트.** 19인치 랙에 볼트로 고정된 하드웨어. 화면이 아니라
> 손에 닿을 듯한 기계여야 한다.

레거시 alias `industrial`이 이 스킨으로 해석된다.

## 철학

Hardware Rack은 다섯 스킨 중 유일한 **정직한 스큐어모피즘**이다. 모든 행이
랙 유닛이고, 모든 컨트롤이 물리 부품이다: 브러시드 메탈 페이스플레이트, 랙
이어(ear), 네 귀퉁이의 일자 나사, 상태 LED, Include 유닛의 패치베이 잭, VST
유닛의 황동 명판. 이 스킨이 사용자에게 주는 약속은 "이 장비는 만질 수 있을
것처럼 생겼고, 실제 하드웨어처럼 행동한다"이다.

"정직한"이 핵심 형용사다. 이 스큐어모피즘은 두 가지 규율로 통제된다.

첫째, **이미지 리소스를 쓰지 않는다.** 나사도, 브러싱 결도, 명판도 전부
QPainter로 그린다. 그래서 DPI에 독립적이고, 토큰을 따라 다크/라이트 두 마감
(다크=베이클라이트/강철, 라이트=크림 알루미늄)으로 일관되게 변한다.

둘째, **하드웨어의 물리 법칙을 따른다.** 위계는 색이나 크기가 아니라 **물리적
깊이**(돌출/평면/함몰)로 만든다. 상태는 램프(LED)가 말한다. 패널에 raw 설정
원문을 인쇄하지 않는다(`showRawPreview = false` — 하드웨어는 원문을 인쇄하지
않는다; `...` 편집 버튼으로는 여전히 닿는다). 각인은 번역하지 않는다 —
`MODULE SELECT`, `NO SIGNAL`, `EAPO-XT SERIES`는 하드웨어에 인쇄된 영문이지
UI 문자열이 아니다(검색 placeholder처럼 진짜 UI 입력 요소만 tr()을 받는다).

가장 미묘한 조항은 디스플레이에 관한 것이다: **하드웨어의 표시창은 패널
마감을 따르지 않는다.** 픽커의 검색창이 라이트 모드에서도 어두운 우물에 녹색
모노 세그먼트로 그려지는 이유다 — 크림색 패널에 박힌 LCD는 여전히 LCD다.

## 불변 규칙

1. **페인트만, 이미지 금지.** 나사·결·명판·LED 전부 QPainter. 비트맵 에셋이
   들어오는 순간 DPI와 토큰 일관성이 깨진다.
2. **모서리 3px = 기계 가공 코너.** 둥글지도 직각도 아닌, 모따기된 금속.
3. **위계 = 물리 깊이.** 돌출(주요 컨트롤) / 평면(라벨) / 함몰(입력 우물).
4. **상태 = 램프.** 활성은 LED 점등, 비활성은 "전원 내린 유닛"(LED 소등 +
   어두운 필름, 하드웨어 자체는 그대로). 색 절제: 액센트는 앰버
   (#F4B860/#B66A00), accent2는 LED 녹색(#5ED0A0/#177A55).
5. **각인 활자.** 라벨은 자간을 띄운 소문자 회피·대문자 각인풍. 콘덴스드
   폰트가 저장소에 없어 자간 띄운 DM Sans로 근사한다(알려진 wish 항목).
6. **이어 존 존중.** 페이스플레이트 양끝의 랙 이어 폭(`RackChrome::earWidth()`)
   은 콘텐츠 금지 구역이다. `prepareCommandRow`가 헤더/본문 여백을 그만큼
   들여 쓴다. VST 행은 명판 폭(`nameplateReserve()`)을 추가로 비운다.
7. **chrome은 RackChrome에.** 그리기 코드는 `RackChrome.{h,cpp}`(약 500줄)에
   모으고 스킨 클래스는 얇은 등록 심(shim)으로 유지한다.

## 빛과 상태의 문법

- **hover** — 페이스플레이트 광택이 오르고(QSS 배경 스텝) 하드웨어
  가장자리가 앰버로 덥혀진다. 픽커 슬롯은 램프가 희미하게 예열된다.
- **selected** — 따뜻한 패널 색(`#332718`/`#FCE8BD`) + 앰버 보더. 픽커
  슬롯은 LED가 앰버로 점등되고 LED 쪽에서 흘러나오는 램프 그라데이션이
  슬롯을 역광으로 비춘다.
- **focused** — focusRing 보더(기계의 선택 프레임).
- **disabled** — **전원 내린 유닛**: LED는 꺼지고 어두운 필름이 덮이지만
  나사·결·명판은 남는다. 장비를 치우는 게 아니라 끄는 것이다.
- 빈 결과(픽커 필터에 0건): 플레이트에 `NO SIGNAL` 각인. 오류 다이얼로그가
  아니라 계기의 무신호 표시다.

## 색의 의미론

다크: 배경 #0B0D0F(랙 내부의 어둠), 카드 #1D2328(강철/베이클라이트), 텍스트
#E6E0D4(따뜻한 상아 — 차가운 흰색 금지). 라이트: 배경 #E7E2D8, 카드 #FFFAEF
(크림 알루미늄), 보더 #C9BFAE(황동기 도는 베이지). 그래프 영역은 깊은
초록빛(#060807, 그리드 #1F3A31) — 오실로스코프 유리의 기억. 채널 그룹은
DottedLine, 배지는 WireframeBorder(채움 없는 와이어 — 패널에 인쇄된 윤곽).
피드백 라운드 2부터 배지 안에는 영어 모노그램 대신 카탈로그 픽토그램이
타입 색 잉크로 인쇄된다(패널 실크스크린의 기호 인쇄 — 미지 명령만 문자
폴백).

## 구성 요소별 표현

### 노브 — 포인터 노브와 패널 인쇄 눈금 (Annex K)

`RackChrome::paintKnob`. 물리 포인터 노브이고, **눈금은 노브가 아니라 패널에
인쇄**된다 — 실제 하드웨어가 그렇듯이. 노브 몸통은 돌출(깊이 위계), 포인터가
값을 가리키고, 활성 상태는 앰버가 맡는다. **노브 캡 위에 값 표시창을 얹지
않는다**(재작업 라운드): 캡을 가로지르는 표시판은 만들 수 없는 하드웨어이고
포인터 선을 잘랐다. 값은 노브 옆의 LED 표시(EditableValue)가 말한다.

인쇄 잉크의 법(AR1 R1): 양끝 스톱 틱은 본문 잉크(text)의 메이저 틱, 중간
틱은 muted 잉크의 마이너 틱이다. **바이폴라(gain) 노브의 0 dB 센터 틱은
플레이트에서 가장 굵고 긴 마크**(앰버, 3px, 안팎으로 연장)다 — 센터
디텐트의 각인. 바이폴라 노브는 데드존 양끝에 `-`/`+` 글리프를 본문 잉크로
각인(1px 오프셋 이중 패스)하고, 유니폴라(freq/Q)는 민짜로 남는다 — 두 종류가
한눈에 갈린다. 포인터는 어두운 그림자 패스 위에 그려져 어느 각도에서도
눈금에 대해 읽힌다.

### 카드(행) chrome

QSS는 기계 가공된 베이스 플레이트(배경+1px 보더+3px 라운드)와 호버 광택만
제공한다. 그 위에 `RackChrome::paintCardChrome`이 페이스플레이트 질감, 랙
이어, 네 나사(슬롯 각도가 제각각 — 사람 손으로 조인 나사), 상태 LED,
Include의 패치베이 잭, VST의 황동 명판을 그린다. 광택 오버레이는 반투명이라
QSS 호버가 비쳐 보인다. 헤더 스트립은 투명(브러시드 메탈이 보여야 하므로).

유닛 안착의 법(AR1 R3): 평상시 보더는 토큰 보더가 아니라 **랙 개구부의
어두운 솔기**(다크 `#060809`, 라이트 `#8F8268`)이고, 그 안쪽에 어두운 안착
틈과 한 방향 작업등을 따르는 모따기(상·좌 = 빛, 하·우 = 그림자)가 둘러져
행 하나하나가 볼트로 고정된 독립 유닛으로 읽힌다. 포커스/선택은 신호색
보더를 유지한다.

브러싱 결의 법(AR1 R4): 수평 브러싱은 줄무늬가 아니라 **결**이다 — 라인별
잉크 농도가 유닛 명령 기반 시드로 결정론적으로 변하고, 드물게 더 밝은
폴리시 라인이 섞인다. 논리 좌표만 사용한다(물리 픽셀 고정 금지, DPI는
페인터 변환이 처리). 같은 결 문법을 마스터 레일, 상단 패널, 픽커
페이스플레이트가 공유한다 — 한 기계에서 잘라낸 판재다.

### 파라미터 영역 — 각인 선택기와 LCD 판독창 (AR1 R2)

파라미터 캡션은 공유 버튼 박스가 아니다. freq/Q 캡션은 실제 모드
선택기(QComboBox, X5 `paramSelector` 프로퍼티)이므로 **패널에 납작하게
각인**된다: muted 잉크의 굵은 소형 활자 + 밑면의 밀링 홈 + 작게 인쇄된
선택기 삼각형(정직성 — 선택기임이 항상 보인다). hover/focus/열림은 버튼
승강이 아니라 앰버 예열로 답한다. gain 캡션(QLabel)은 같은 각인 팔레트를
입되 모드가 없으므로 삼각형이 없다. 전원 내린 유닛에서는 선택기와 같은
농도로 함께 바랜다.

값 박스(X1 `valueScrub` 스핀박스)는 **플레이트에 박힌 LCD 판독창**이다:
두 모드 모두 어두운 유리 + 녹색 세그먼트 잉크(모노 굵은 활자) — 디스플레이는
패널 마감을 따르지 않는다는 표시창 조항의 적용이다. 포커스는 앰버 서비스
엣지가 켜진다. 숫자를 세로로 드래그하면 스크럽된다.

### 타입 표시

타입별 **플레이트 마감**이 다르다: Include는 잭이 박힌 인서트 유닛, VST는
리벳 명판이 붙은 유닛, 일반 DSP는 표준 페이스플레이트 + 각인 식별자. 색
배지가 아니라 부품 구성이 타입을 말한다.

### 판 위의 직접 페인팅 (재작업 라운드)

페이스플레이트에 앉는 커스텀 위젯(노브, 값 스크럽, 채널 배지, 라우팅 베드,
램프, 각인 라벨, LCD 우물)은 자기 픽셀만 그린다. 전역 `QWidget {
background }` 기본 도장이 위젯 사각형 밑에 앱 배경색 패치를 깔면 각인이
'판에 새긴 글'이 아니라 '붙여 놓은 딱지'로 읽힌다 — 프리앰프 노브 주변의
어두운 사각형이 최악 사례였다. rack 시트가 이 클래스들을 클래스 선택자로
투명화한다(rack_*.qss의 `AudioKnob, EditableValue, …` 규칙). 선택자가
닿으려면 해당 클래스에 **Q_OBJECT가 있어야 한다**(없으면 className이
QWidget으로 보고되어 규칙이 빗나간다). 함몰면은 표시창 조항의 LCD/LED
우물, 인서트 유닛의 함몰 베드처럼 **부품으로 설계된 것**만 허용된다.

### 참조 카드 — 서비스 컨디션의 유닛 (AR2)

Include/Convolution/MultiConvolution/VST 행의 본문은
`RackReferenceCardView`가 그리는 물리 부품 구성이다: 왼쪽 베젤 상태 램프
(RackChrome::paintLed 문법) → (멀티컨볼루션이면 R2 각인 선택기 문법의
출력 채널 콤보) → 각인 라벨 스트립(자간 띄운 캡션 `PATCH`/`IR PROGRAM`/
`MODULE` + 와이어프레임 스탬프 `VST2`/`VST3`/`ABS` + 혼합대소문자 이름
각인 + muted 위치 서브 각인 — 컨테이너 접두 `Surround\` 형태로, 폴더가
이름의 하위 항목으로 읽히지 않게) → **함몰 LCD 판독창**(IR 판독값, 두 모드
모두 어두운 유리 + 녹색 세그먼트 — 표시창 조항) → 기계 버튼 열. 결손은
서비스 컨디션이다: 램프가 적색으로 점등하고 이름 각인이 물러나며 앰버
`NOT FOUND` 각인(미번역) 하나와 `LOCATE` 각인 캡이 붙는다 — 패널 전면의
빨간 대문자 문장은 구조적으로 불가능하다. 빈 참조는 뽑힌 모듈의 빈
슬롯(램프 소등 + muted `EMPTY SLOT` 각인)이고, 비활성은 전원 내린
유닛(램프 강제 소등, 각인·세그먼트 감광, 하드웨어는 남는다)이다. 공유
`RefPathEdit`는 프로그래밍 LCD로 입힌다.

### Copy 라우팅 — 라우팅 매트릭스 버튼 필드 (HardwarePatchbay)

크로스포인트 격자이되 각 교차점이 **정사각 조명 래칭 버튼**이다. 실제
라우팅 매트릭스가 교차점에 쓰는 부품이 이것이고, 필터 카드의 로터리
다이얼을 축소해 심는 것은 금지한다(큰 다이얼 = 연속 파라미터, 작은 사각
버튼 = 래칭 선택 — 부품이 다르면 조작 문법도 다르다). 브러시드 패널
(surface를 위아래로 8% 밝게/어둡게 한 세로 그라데이션) 위에 버튼 뱅크가
**함몰 서브패널**(그늘진 윗변 + 점등된 아랫입술, 캡처 웰의 함몰 문법)에
장착되고, 행=출력, 열=입력 채널이 트래킹 각인으로 붙는다. 휴지 교차점은
민짜 돌출 캡(각인 딤플 하나)이고, 라우팅된 교차점은 Device·Channel 캡과
같은 latch-down 법으로 **눌려 잠긴 캡**(반전 베벨, 면 1px 하강)이 되어
캡 아래 램프가 켜진다. legend 법: **유니티 라우팅은 legend 없이 원형
램프 창(콘솔 ON 버튼의 LED 점 + 후광)만 켠다**(켜진 래치가 이미 '그대로
통과'를 말하고, 유니티에 값을 인쇄하면 x1이든 0dB든 볼륨/뮤트 오독을
부른다). 램프 창의 모양은 채워진 원이어야 한다 — 가로 슬릿은 빼기(−)로,
윤곽 링은 글자 O로 오독된다(2026-07-04 사용자 판정). 계수가 유니티를 벗어난
때만 램프 빛을 받는 **버튼 legend**가 캡 위에 인쇄된다 — 극성 반전은
INV, 나머지는 계수 원문(0.5, -0.7), ㏈로 적힌 값은 ㏈ 원문. 음수 게인은
danger 램프다. 클릭=유니티 토글, 더블클릭=값 편집, 빈 값=제거. 장치 채널
전체가 시딩되어 편집 표면은 유지되되, 패널은 접힌다(라운드 4): 기본
장착은 명령이 관여하는 채널뿐이고(빈 명령이면 앞 두 장치 채널이 대표),
나머지 장치 채널은 필드 아래 페이스플레이트 스트립의 **확장 래치** 뒤에
있다 — 민짜 캡 legend `+N`, 눌러 잠그면 전체 레이아웃이 장착되며 legend
`ALL`의 latch-down 캡이 된다(같은 한 벌의 latch 법; 곁에 CHANNELS 트래킹
각인). 그 옆의 `ADD` 캡은 옆자리 인라인 편집기(LCD 자리)를 열어 새 가상
채널 라벨을 페이스플레이트에 패치하고, 가상 채널 라벨은 호버 시 각인 `x`
타깃을 드러내 떼어낼 수 있다(장치 채널은 떼어지지 않고 접힐 뿐이다).

MultiConvolution 카드가 같은 버튼 필드를 고정 소스 모드(RoutingPortModel)로
재사용한다: 열이 IR 파일의 채널 번호로 고정되고, 팩터가 없으므로 버튼은
패치 여부만 말한다. legend 없이 캡 가운데 같은 **원형 램프 창**만
켜진다(패치 포인트에 게인 legend가 남아 있으면 없는 조절 능력을
약속하는 셈이다). 접기와 확장 래치도 없다 — 매핑된 대상이 필드의 전부다.
매핑 스트립의 캡션(`#MultiConvolutionMappingCaption`)은 다른 랙 캡션과 같은
대문자 트래킹 각인이다.

### 장치·채널·주석·스테이지 카드 (Phase 2)

네 카드는 '한 기계의 네 부품'이다. 램프의 **위치**로 부품을 가른다. Device
= 래칭 라우팅 스위치(재생 = 돌출 캡, 캡처 = 함몰 입력 우물, 미설치 = 한
단계 물러난 민짜 블랭크). 스위치 캡은 실제 기구다: `:pressed`가 캡을
중립 금속으로 가라앉히고, 체결된 스위치는 **눌려 잠긴 캡**(반전 베벨 =
그늘진 윗변 + 점등된 아랫입술, 반전 그라디언트, 패딩 시프트로 라벨 1px
하강)이 캡 전체 앰버 백라이트로 남는다 — 램프가 켜진 채 솟아 있는 캡은
스큐어모피즘 위반이라 금지. Channel = 캡 아래
램프창(border-bottom 2px)이 켜지는 콘솔 어사인 키(가상 좌석은 채움 없는
점선 와이어 = 패널 인쇄 윤곽, 신호가 앉으면 램프만 진짜로 켜짐) — Device와
같은 latch-down 문법, 램프 위치만 다르다. Stage =
캡 상단 2px 주얼 램프가 켜지는 INSERT POINT 래칭 스위치(capture 키는 입력측
이라 함몰 문법 공유, 체결되면 같은 주얼)이고, 두 레인 캡션
(PLAYBACK/RECORDING)과 체인 화살표는 페이스플레이트에 인쇄된 뮤트 트래킹
각인이다. 마스터(All devices/ALL)는 이
기계의 유일한 **녹색(accent2) = 버스 전체** 규약으로 켜지고, 전원 내린
마스터도 녹색 기억을 유지한다(`[all*]:checked:disabled` 결합 선택자 —
타입 속성과 :checked의 특이도 동점이 램프를 가리는 함정의 재발 방지).
같은 특이도 계층 안에서는 순간 눌림 규칙을 맨 뒤에 두어, 손가락이 얹힌
캡이 언제나 눌린 얼굴을 보이게 한다.
Comment의 물성은 다이모 엠보싱 라벨 테이프다: 각인은 공장 인쇄물이고
주석은 현장에서 붙인 것이므로, 광택 검정 스트립 + 양각 상아색(#F1E9D8)
활자로 두 마감 모두에서 검정을 유지한다(LCD와는 활자로 구분: LCD = 녹색
모노 세그먼트). 사용자 데이터라 대문자 변환은 걸지 않는다. 네 에디터
배경은 투명(판 위 직접 페인팅 법).

### 리스트 chrome — 빈 랙 베이와 서비스 슬롯 (라운드 3)

카드 추가·삽입의 공유 계약(README)에 대한 rack의 답은 랙 자체의 빈자리다.

- **맨 끝 add row = 빈 랙 베이.** 블랭크 패널이 빠진 개구부로 랙 내부가
  들여다보인다. 내부는 두 마감 모두 어둡다(랙 속에는 마감이 없다 — 표시창
  조항과 같은 물리적 정직). 개구부의 챔퍼는 페이스플레이트의 역상(윗변
  그림자 = 위 유닛의 처마, 아랫입술 = 작업등), 이어 존 자리에는 마운팅
  레일과 빈 볼트 구멍 두 쌍이 유닛의 이어를 기다린다. 베이 안의 스텐실은
  휴지 시 `EMPTY BAY`, 호버 시 `INSTALL MODULE`로 답하며 앰버로
  예열된다(미번역 각인 — 번역 캡션은 위젯 툴팁이 책임진다. state.label은
  쓰지 않는다). 호버/눌림은 베젤의 앰버 라인이지 버튼 승강이 아니다.
- **첫 경계 삽입선 = 서비스 슬롯의 앰버 예열 라인.** 스트로크만 쓴다:
  기계 가공 홈의 그림자 선, 그 위의 앰버 열선, 이어 그루브 위치의 짧은
  틱 두 개. 휴지 시에는 아무것도 그리지 않는다(계약). 원판(disc)이나
  채움을 더하지 않는다 — 슬롯이 달아오르는 것이지 부품이 생기는 것이
  아니다.

### GraphicEQ 카드 — 오실로스코프 표시창 (라운드 3 재작업)

응답 플롯은 GraphicEQPlotWidget의 픽셀 전부를 스킨이 그리는 **오실로스코프
표시창**이다(`RackChrome::paintGraphicEqPlot`, 헌법 7조대로 그리기는
RackChrome에 두고 RackSkin은 얇은 심). 두 마감 모두 어두운 인광 유리
우물이다 — 크림 패널에 박힌 스코프도 스코프다(표시창 조항). 베젤은 함몰
문법(그늘진 윗변의 처마 그림자 + 점등된 아랫입술)이고, 포커스는 LCD와 같은
앰버 서비스 엣지로 답한다.

- **그래티큘:** #1F3A31 계열 스코프 그리드(다크는 graphGridMinor 토큰
  그대로, 라이트의 그리드 토큰은 패널 도료라 유리에 들어오지 못한다).
  직선은 AA 없는 크리스프 1px, 메이저는 한 단계 밝다. 0 dB 축은 인광
  틴트의 중심선 + 스코프 특유의 미세 해시 틱이다.
- **라벨:** 유리 여백에 세그먼트 잉크(시트의 LCD 팔레트)로 새긴 숫자 각인
  (미번역 — 숫자다). 커서 판독은 유리 안 우상단의 밝은 세그먼트다.
- **곡선:** 녹색 인광(accent2; 라이트 토큰은 도료라 유리 위에서 발광
  강도로 끌어올린다). 글로우는 넓고 옅은 스트로크를 겹쳐 위조한다(이펙트
  금지). 0 dB 축까지의 옅은 채움이 잔광이다. 빔은 그래티큘 영역 안에만
  산다(관이 트레이스를 가리듯).
- **노드:** 발광 조정 도트. 휴지 = 옅은 돔, 호버 = 예열(돔이 부풀고
  밝아짐), 선택 = 점등 코어 + 조정 칼라 링, 키보드 대상은 표시창이
  포커스를 쥔 동안 앰버 서비스 링을 두른다. 상태 사다리 휴지<호버<선택.
- **bandLocked(15/31):** 각 노드가 0 dB 축에서 세그먼트 레벨 사다리를
  내린다 — 하드웨어 분석기의 계단식 컬럼 읽기.
- **비활성:** 전원 내린 표시창. 그리드·라벨·트레이스가 서비스 농도로
  감광하고 노드는 어두운 돔으로 남지만, 유리와 베젤은 그대로다.

정밀 입력은 플롯 아래 판독 스트립이 맡는다: 캡션(#GraphicEQBandCaption,
\#GraphicEQReadoutLabel)은 대문자 트래킹 각인, Freq/Gain 박스는 X1 LCD
판독창 문법을 그대로 입고, 밴드 레이아웃 캡션은 R2의 각인 선택기
(paramSelector)를 탄다. 다섯 액션 버튼은 표준 기계 버튼(돌출 캡, 눌림 시
침강)이다. 플롯·스트립 컨테이너는 판 위 직접 페인팅 법에 따라 투명하다.

### 맨텍스트 행 — AUX 유닛의 프로그래밍 LCD (라운드 3)

해석되지 않는 줄(맨 노트, `If` 같은 프로그래밍 명령)은 AUX 유닛이고, 원문은
**프로그래밍 LCD**에 as-written으로 태운다: 어두운 유리 + 녹색 모노 세그먼트,
두 마감 공통. 행 위젯이 토큰 인라인 스타일을 깔아 QSS로는 못 이기므로
`prepareCommandRow`가 `FilterCardRawText`에 직접 입힌다. 전원 내린 유닛은
세그먼트가 감광한다. `>_` 프롬프트 글리프는 기본(뮤트 모노 잉크)을 그대로
쓴다 — 이미 패널 인쇄로 읽히므로 더 얹지 않는다.

### 업데이트 토스트 — 서비스 노티스 (라운드 3)

위젯이 토큰 카드(면 + 헤어라인 보더 + 앰버 뉴스 킬)를 직접 그리므로 rack은
잉크만 답한다: 메시지는 따뜻한 본문 잉크의 문장이다(번역된 UI 데이터 —
각인이 아니므로 대문자·트래킹 금지). 닫기 캡은 작은 기계 버튼로, 호버에서
앰버로 덥혀지고 눌리면 침강한다. LCD로 만들지 않는다 — 알림은 판독값이
아니라 서비스 태그다.

### 필터 픽커 — 1U 모듈 프리셋 브라우저

- 브러시드 페이스플레이트: 세로 광택 + 가로 브러싱 라인, 기계 가공된 1px
  엣지와 점등된 상단 베젤.
- 네 귀퉁이의 일자 나사(슬롯 각도 제각각), `MODULE SELECT` 각인 헤더 + 녹색

  **두 모드 모두에서** — 디스플레이는 패널 마감을 따르지 않는다.
- 카테고리 = 리벳 박힌 각인 섹션 플레이트. 항목 = 베젤 달린 패널 LED가 붙은
  라벨 슬롯.
- 램프 감광의 법(AR1 R5): **비점등 슬롯 램프는 한 단계 물러난다** — 옅은
  베젤 잉크, 반투명 돔, 희미한 스펙큘러. 슬롯 기둥이 불릿 나열로 읽히지
  않도록, 시선은 점등(선택)과 예열(호버) 램프만 끈다.
- 갤러리 쇼케이스: hover는 두 번째 슬롯의 램프 예열(선택 슬롯의 점등과 한
  장에 대비), 빈 검색은 LCD에 죽은 검색어 + 플레이트의 `NO SIGNAL` 각인.
- 모든 chrome은 RackChrome의 그리기 문법을 재현해 카드 페이스플레이트와
  시각적으로 연속이다.

- 평면(flat) 디자인 어휘 혼입: 채운 색 배지, 그림자 없는 순수 플랫 카드,

- 페이스플레이트에 raw 설정 원문 인쇄.
- 각인 문구에 tr() 적용(하드웨어 인쇄물이다). 단, 진짜 입력 요소의
  placeholder는 번역한다.
- 이어 존에 콘텐츠 배치(나사·LED와 충돌한다).
- 차가운 흰색/회색 텍스트. 이 스킨의 잉크는 따뜻하다.

## 이웃 스킨과의 경계

깊이를 다루는 스킨이라는 점에서 **soft**와 비교되지만, soft의 고도는 명도
스텝의 추상이고 rack의 깊이는 부품의 물리다(나사·베젤·함몰 우물). 점등
어휘를 쓴다는 점에서 **matrix**와 비교되지만, matrix의 LED는 보드 위의 추상
신호(셀의 점등)이고 rack의 LED는 베젤에 박힌 물리 부품이다. rack에서 격자
좌표나 모노 코드 셀이 보이면 matrix를 침범한 것이다.

## 새 요소를 이 스킨답게 만드는 법

6. 이어 존과 명판 예약 폭을 침범하지 않는가?
7. 각인 문구와 UI 문자열을 구분했는가?
