# Hardware Rack (`rack`) 디자인 헌법

> **앰프 페이스플레이트.** 19인치 랙에 볼트로 고정된 하드웨어. 화면이 아니라
> 손에 닿을 듯한 기계여야 한다.

레거시 alias `industrial`이 이 스킨으로 해석된다.

## 철학

Hardware Rack은 다섯 스킨 중 유일한 정직한 스큐어모피즘이다. 모든 행이 랙
유닛이고 모든 컨트롤이 물리 부품이다(브러시드 메탈 페이스플레이트, 랙
이어(ear), 네 귀퉁이의 일자 나사, 상태 LED, Include 유닛의 패치베이 잭, VST
유닛의 황동 명판). 이 스킨이 사용자에게 주는 약속은 "이 장비는 만질 수 있을
것처럼 생겼고, 실제 하드웨어처럼 행동한다"이다.

모든 스트로크의 공식 타이브레이커는 한 질문이다. **"이것이 하드웨어
페이스플레이트에 있을 물건인가?"** 나사, 홈, LED, 각인 인쇄는 '예'다. 글로우,
값 호, 추상 장식은 '아니오'다. 예외는 둘뿐이다. 얇은 키보드 포커스 링과 호버
하이라이트는 UI에 꼭 필요해서 남기되, 의도적으로 작게 유지한다.

## 불변 규칙

아래 조항은 모든 구성 요소가 공유하므로, 구성 요소 절은 조항 이름(표시창
조항, paintLed 문법, 전원 내림 등)으로만 가리키고 되풀이하지 않는다.

1. **페인트만, 이미지 금지.** 나사·결·명판·LED 전부 QPainter로 그린다. 비트맵
   에셋이 들어오는 순간 DPI 독립성과 토큰 일관성(다크=베이클라이트/강철,
   라이트=크림 알루미늄)이 깨진다.
2. **모서리 3px = 기계 가공 코너.** 둥글지도 직각도 아닌, 모따기된 금속으로
   그린다.
3. **위계 = 물리 깊이.** 위계는 색이나 크기가 아니라 돌출(주요 컨트롤) /
   평면(라벨) / 함몰(입력 우물)로 만든다. 함몰면은 부품으로 설계된
   것(LCD/LED 우물, 인서트 유닛의 함몰 베드)만 허용한다.
4. **상태 = 램프, 램프 = paintLed 문법.** 상태는 LED가 말하고, 모든 램프는
   paintLed 문법(베젤 링 + 돔 + 스펙큘러, 후광은 점등 시에만)을 거친다. 다크
   마감에서 맨 발광 원반은 부품이 아니라 도료로 읽힌다. (판례: 동적 명령어
   라운드)
5. **전원 내림 = 비활성.** 비활성은 "전원 내린 유닛"이다. LED를 끄고 어두운
   필름을 덮되 나사·결·명판·각인은 남긴다. 장비를 치우는 것이 아니라 끄는
   것이다.
6. **색 절제.** 액센트는 앰버(#F4B860/#B66A00), accent2는 LED
   녹색(#5ED0A0/#177A55)이다. 색은 램프와 각인에만 산다.
7. **표시창 조항.** 디스플레이(LCD, 판독창, 스코프 유리)는 패널 마감을 따르지
   않고, 두 마감 모두 어두운 우물 + 발광 세그먼트로 그린다. 크림색 패널에
   박힌 LCD도 여전히 LCD이기 때문이다.
8. **각인 조항.** 라벨은 자간을 띄운 대문자 각인풍 활자로 쓴다(콘덴스드
   폰트가 저장소에 없어 자간 띄운 DM Sans로 근사, 알려진 wish 항목). 각인
   문구(`MODULE SELECT`, `NO SIGNAL`, `EAPO-XT SERIES` 등)는 하드웨어
   인쇄물이지 UI 문자열이 아니므로 번역하지 않고, 검색 placeholder 같은
   진짜 UI 입력 요소만 tr()을 받는다.
9. **raw 원문 인쇄 금지.** 패널에 raw 설정 원문을 인쇄하지 않는다.
   하드웨어는 원문을 인쇄하지 않으며, 헤더의 코드 마크(`</>` 아이콘, 원본
   명령 편집)로는 여전히 닿는다. (2026-08 밀도 라운드부터 전 스킨 공통
   규범이다. 공용 raw 미리보기 스트립이 폐지되었고, 후속 라운드에서 헤더
   요약의 파라미터 에코도 폐지되었다. 원본 명령 편집 아이콘이 연필이
   아닌 것도 규범이다: 연필은 Include 카드의 '파일 내용 편집'이 쓴다.)
10. **이어 존 불가침.** 페이스플레이트 양끝의 랙 이어
    폭(`RackChrome::earWidth()`)은 콘텐츠 금지 구역이다. `prepareCommandRow`가
    헤더/본문 여백을 그만큼 들여 쓴다. VST 행은 명판
    폭(`nameplateReserve()`)을 추가로 비운다.
11. **chrome은 RackChrome에.** 그리기 코드는 `RackChrome.{h,cpp}`(약 500줄)에
    모으고 스킨 클래스는 얇은 등록 심(shim)으로 유지한다.

## 빛과 상태의 문법

- **hover:** 페이스플레이트 광택이 오르고(QSS 배경 스텝) 하드웨어 가장자리를
  앰버로 덥힌다. 픽커 슬롯은 램프를 희미하게 예열한다.
- **selected:** 따뜻한 패널 색(`#332718`/`#FCE8BD`)과 앰버 보더를 입는다.
  픽커 슬롯은 LED가 앰버로 점등되고, LED 쪽에서 흘러나오는 램프 그라데이션이
  슬롯을 역광으로 비춘다.
- **focused:** focusRing 보더(기계의 선택 프레임)를 두른다.
- **disabled:** 불변 규칙 5의 전원 내린 유닛으로 그린다.
- **빈 결과(픽커 필터에 0건):** 플레이트에 `NO SIGNAL`을 각인한다. 오류
  다이얼로그가 아니라 계기의 무신호 표시다.

## 색의 의미론

다크는 배경 #0B0D0F(랙 내부의 어둠), 카드 #1D2328(강철/베이클라이트), 텍스트
#E6E0D4(따뜻한 상아. 차가운 흰색 금지)를 쓴다. 라이트는 배경 #E7E2D8, 카드
#FFFAEF(크림 알루미늄), 보더 #C9BFAE(황동기 도는 베이지)를 쓴다. 그래프
영역은 깊은 초록빛(#060807, 그리드 #1F3A31)으로, 오실로스코프 유리의
기억이다. 채널 그룹은 DottedLine을 쓰고, 배지는 WireframeBorder(채움 없는
와이어, 패널에 인쇄된 윤곽)를 쓴다. 배지 안에는 영어 모노그램 대신 카탈로그
픽토그램을 타입 색 잉크로 인쇄한다(패널 실크스크린의 기호 인쇄, 미지 명령만
문자 폴백). (판례: 피드백 r2)

## 구성 요소별 표현

### 노브: 포인터 노브와 패널 인쇄 눈금 (Annex K)

`RackChrome::paintKnob`이 그리는 물리 포인터 노브다. 몸통은 돌출이고,
포인터가 값을 가리키며, 활성 상태는 앰버가 맡는다.

- 눈금은 노브가 아니라 패널에 인쇄한다. 실제 하드웨어가 그렇다. (판례:
  Annex K)
- 노브 캡 위에 값 표시창을 얹지 않는다. 캡을 가로지르는 표시판은 만들 수
  없는 하드웨어이고 포인터 선을 자른다. 값은 노브 옆의 LED
  표시(EditableValue)가 말한다. (판례: AR2 재작업)
- 인쇄 잉크의 법: 양끝 스톱 틱은 본문 잉크(text)의 메이저 틱으로, 중간 틱은
  muted 잉크의 마이너 틱으로 그린다. 바이폴라(gain) 노브의 0 dB 센터 틱은
  플레이트에서 가장 굵고 긴 마크(앰버, 3px, 안팎으로 연장)로 새긴다(센터
  디텐트의 각인). 바이폴라 노브는 데드존 양끝에 `-`/`+` 글리프를 본문 잉크로
  각인하고(1px 오프셋 이중 패스), 유니폴라(freq/Q)는 민짜로 남겨 두 종류가
  한눈에 구분되게 한다. 포인터는 어두운 그림자 패스 위에 그려 어느
  각도에서도 눈금과 구분되게 한다. (판례: AR1 R1)

### 카드(행) chrome

QSS는 기계 가공된 베이스 플레이트(배경 + 1px 보더 + 3px 라운드)와 호버
광택만 제공한다. 그 위에 `RackChrome::paintCardChrome`이 페이스플레이트
질감, 랙 이어, 네 나사(슬롯 각도가 제각각인, 사람 손으로 조인 나사), 상태
LED, Include의 패치베이 잭, VST의 황동 명판을 그린다. 광택 오버레이는
반투명이라 QSS 호버가 비쳐 보이고, 헤더 스트립은 투명하다(브러시드 메탈이
보여야 한다).

- 유닛 안착의 법: 평상시 보더는 토큰 보더가 아니라 랙 개구부의 어두운
  솔기(다크 `#060809`, 라이트 `#8F8268`)로 그리고, 그 안쪽에 어두운 안착
  틈과 한 방향 작업등을 따르는 모따기(상·좌 = 빛, 하·우 = 그림자)를 두른다.
  행 하나하나가 볼트로 고정된 독립 유닛으로 읽히게 하기 위해서다.
  포커스/선택은 신호색 보더를 유지한다. (판례: AR1 R3)
- 브러싱 결의 법: 수평 브러싱은 줄무늬가 아니라 결이다. 라인별 잉크 농도를
  유닛 명령 기반 시드로 결정론적으로 바꾸고, 드물게 더 밝은 폴리시 라인을
  섞는다. 논리 좌표만 사용한다(물리 픽셀 고정 금지, DPI는 페인터 변환이
  처리한다). 마스터 레일, 상단 패널, 픽커 페이스플레이트가 같은 결 문법을
  공유한다(한 기계에서 잘라낸 판재). (판례: AR1 R4)

### 파라미터 영역: 각인 선택기와 LCD 판독창 (AR1 R2)

freq/Q 캡션은 실제 모드 선택기(QComboBox, X5 `paramSelector` 프로퍼티)이고,
값 박스는 X1 `valueScrub` 스핀박스다.

- 선택기 캡션은 공유 버튼 박스가 아니라 패널에 납작하게 각인한다. muted
  잉크의 굵은 소형 활자, 밑면의 밀링 홈, 작게 인쇄된 선택기 삼각형으로
  그린다(선택기임이 항상 보이는 정직성). hover/focus/열림은 버튼 승강이
  아니라 앰버 예열로 답한다. gain 캡션(QLabel)은 같은 각인 팔레트를 입되
  모드가 없으므로 삼각형을 붙이지 않는다. 전원 내린 유닛에서는 선택기와
  같은 농도로 함께 바랜다.
- 값 박스는 플레이트에 박힌 LCD 판독창이다(표시창 조항, 녹색 세그먼트
  잉크의 모노 굵은 활자). 포커스는 앰버 서비스 엣지를 켠다. 숫자를 세로로
  드래그하면 스크럽된다.

### 타입 표시

타입은 색 배지가 아니라 부품 구성이 말한다. Include는 잭이 박힌 인서트
유닛으로, VST는 리벳 명판이 붙은 유닛으로, 일반 DSP는 표준 페이스플레이트에
각인 식별자를 단 유닛으로 그린다.

### 판 위의 직접 페인팅 (AR2 재작업)

페이스플레이트에 앉는 커스텀 위젯(노브, 값 스크럽, 채널 배지, 라우팅 베드,
램프, 각인 라벨, LCD 우물)은 자기 픽셀만 그린다. 전역 `QWidget {
background }` 기본 도장이 위젯 사각형 밑에 앱 배경색 패치를 깔면 각인이
'판에 새긴 글'이 아니라 '붙여 놓은 딱지'가 되기 때문이다. rack 시트가 이
클래스들을 클래스 선택자로 투명화한다(rack_*.qss의 `AudioKnob,
EditableValue, …` 규칙). 선택자가 닿으려면 해당 클래스에 **Q_OBJECT가
있어야 한다**(없으면 className이 QWidget으로 보고되어 규칙이 빗나간다).
(판례: AR2 재작업)

### 참조 카드: 서비스 컨디션의 유닛 (AR2)

Include/Convolution/MultiConvolution/VST 행의 본문은
`RackReferenceCardView`가 그리는 물리 부품 구성이다. 순서는 왼쪽 베젤 상태
램프, (멀티컨볼루션이면 AR1 R2 각인 선택기 문법의 출력 채널 콤보), 각인 라벨
스트립, 함몰 LCD 판독창(IR 판독값, 표시창 조항), 기계 버튼 열이다.

- 라벨 스트립은 자간 띄운 캡션(`PATCH`/`IR PROGRAM`/`MODULE`), 와이어프레임
  스탬프(`VST2`/`VST3`/`ABS`), 혼합대소문자 이름 각인, muted 위치 서브
  각인으로 구성한다. 위치는 컨테이너 접두 `Surround\` 형태로 적어 폴더가
  이름의 하위 항목으로 읽히지 않게 한다.
- 결손은 서비스 컨디션으로 표현한다(총강 조문 3의 rack 형태: 베젤 LED가
  먼저 말한다). 램프가 적색으로 점등하고 이름 각인이 물러나며, 앰버
  `NOT FOUND` 각인 하나와 `LOCATE` 각인 캡을 붙인다. 패널 전면의 빨간
  대문자 문장은 구조적으로 불가능하기 때문이다. (판례: AR2)
- 빈 참조는 뽑힌 모듈의 빈 슬롯(램프 소등 + muted `EMPTY SLOT` 각인)으로,
  비활성은 전원 내린 유닛으로 그린다. 공유 `RefPathEdit`는 프로그래밍
  LCD로 입힌다.

### VST 버스: 판 위의 래치 캡 (VST3Bus)

라벨 스트립과 기계 버튼 사이, IR 유닛이 LCD를 다는 자리에 각인 `IN`/`OUT`과
래칭 버튼 캡 두 개를 판 위에 직접 장착한다.

- 총강 조문 2의 rack 형태: 로드된 ABI는 헤더 오른쪽의 황동 브랜드 명판이
  새긴다(`VST3`/`VST2`, 로드 전에는 패밀리 브랜드 `VST`). 명판이 이미 게시한
  사실을 본문의 와이어프레임 포맷 스탬프로 되풀이하지 않는다. (판례: r3)
- 캡 주위에 함몰 서브패널 테두리를 두르지 않는다. 캡이 이미 부품이고,
  하드웨어는 버튼 두 개를 액자에 넣지 않는다. (판례: r2)
- 총강 조문 6의 rack 형태: 캡은 휴지에 돌출(윗변 하이라이트)이고, 메뉴가
  잡는 동안 latch-down(반전 베벨, 인쇄가 1px 내려앉는다)이며, 호버·포커스는
  앰버 보더 예열이다. 리프트는 없다.
- 총강 조문 5의 rack 형태: 방향은 판에 새긴 화살(1px 아래 명암 패스 +
  잉크)로 그린다. (판례: r1)
- 판정은 paintLed 문법의 베젤 LED가 말한다. 수락은 녹색, 거부는 적색, VST2
  잔존 키는 앰버다. 총강 조문 1의 rack 형태: 거부는 적색 LED 하나로 끝나며,
  옆에 'Rejected' 각인을 붙이지 않는다. (판례: r2)
- 페어 각인(` - ` 연결)은 Auto 협상의 체결 판독에만 쓰고, 문장은 카드 상태
  줄의 몫이다. 전원 내림에는 하드웨어만 남는다.

### Copy 라우팅: 라우팅 매트릭스 버튼 필드 (HardwarePatchbay)

크로스포인트 격자이되 각 교차점이 정사각 조명 래칭 버튼이다. 실제 라우팅
매트릭스가 교차점에 쓰는 부품이 이것이다. 브러시드 패널(surface를 위아래로
8% 밝게/어둡게 한 세로 그라데이션) 위의 함몰 서브패널(그늘진 윗변 + 점등된
아랫입술, 캡처 웰의 함몰 문법)에 버튼 뱅크를 장착하고, 행=출력, 열=입력
채널을 트래킹 각인으로 붙인다.

- 필터 카드의 로터리 다이얼을 축소해 심지 않는다. 큰 다이얼은 연속
  파라미터, 작은 사각 버튼은 래칭 선택이다(부품이 다르면 조작 문법도
  다르다).
- 휴지 교차점은 민짜 돌출 캡(각인 딤플 하나)으로 그리고, 라우팅된 교차점은
  Device·Channel 캡과 같은 latch-down 법의 눌려 잠긴 캡(반전 베벨, 면 1px
  하강)으로 바꿔 캡 아래 램프를 켠다(총강 조문 6의 rack 형태).
- legend 법: 유니티 라우팅은 legend 없이 원형 램프 창(콘솔 ON 버튼의 LED 점
  + 후광)만 켠다. 켜진 래치가 이미 '그대로 통과'를 말하고, 유니티에 값을
  인쇄하면 x1이든 0dB든 볼륨/뮤트 오독을 부른다. 램프 창의 모양은 채워진
  원이어야 한다. 가로 슬릿은 빼기(-)로, 윤곽 링은 글자 O로 오독된다.
  (판례: 2026-07-04 사용자 판정)
- 계수가 유니티를 벗어난 때만 램프 빛을 받는 버튼 legend를 캡 위에
  인쇄한다. 극성 반전은 INV, 나머지는 계수 원문(0.5, -0.7), ㏈로 적힌 값은
  ㏈ 원문이다. 음수 게인은 danger 램프다.
- 클릭은 유니티 토글, 더블클릭은 값 편집, 빈 값은 제거다. 장치 채널 전체를
  시딩해 편집 표면은 유지한다.
- 패널은 접는다. 기본 장착은 명령이 관여하는 채널뿐이고(빈 명령이면 앞 두
  장치 채널이 대표), 나머지 장치 채널은 필드 아래 페이스플레이트 스트립의
  확장 래치 뒤에 둔다. 래치는 민짜 캡 legend `+N`이고, 눌러 잠그면 전체
  레이아웃이 장착되며 legend `ALL`의 latch-down 캡이 된다(같은 한 벌의
  latch 법, 곁에 CHANNELS 트래킹 각인). (판례: 라운드 4)
- `ADD` 캡은 옆자리 인라인 편집기(LCD 자리)를 열어 새 가상 채널 라벨을
  페이스플레이트에 패치한다. 가상 채널 라벨은 호버 시 각인 `x` 타깃을
  드러내 떼어낼 수 있다(장치 채널은 떼어지지 않고 접힐 뿐이다).
- MultiConvolution 카드는 같은 버튼 필드를 고정 소스
  모드(RoutingPortModel)로 재사용한다. 열이 IR 파일의 채널 번호로 고정되고
  팩터가 없으므로, 버튼은 legend 없이 캡 가운데 같은 원형 램프 창만
  켠다(패치 포인트에 게인 legend가 남아 있으면 없는 조절 능력을 약속하는
  셈이다). 접기와 확장 래치도 없다(매핑된 대상이 필드의 전부다). 매핑
  스트립의 캡션(`#MultiConvolutionMappingCaption`)은 다른 랙 캡션과 같은
  대문자 트래킹 각인이다.

### 장치·채널·주석·스테이지 카드 (Phase 2)

네 카드는 '한 기계의 네 부품'이고, 램프의 위치로 부품을 구분한다.

- Device는 래칭 라우팅 스위치다(재생 = 돌출 캡, 캡처 = 함몰 입력 우물,
  미설치 = 한 단계 물러난 민짜 블랭크). `:pressed`는 캡을 중립 금속으로
  가라앉히고, 체결된 스위치는 눌려 잠긴 캡(반전 베벨 = 그늘진 윗변 + 점등된
  아랫입술, 반전 그라디언트, 패딩 시프트로 라벨 1px 하강)이 캡 전체 앰버
  백라이트로 남는다. 램프가 켜진 채 솟아 있는 캡은 스큐어모피즘 위반이라
  금지한다.
- Channel은 캡 아래 램프창(border-bottom 2px)이 켜지는 콘솔 어사인 키다.
  가상 좌석은 채움 없는 점선 와이어(패널 인쇄 윤곽)로 그리고, 신호가 앉으면
  램프만 진짜로 켠다. Device와 같은 latch-down 문법이고 램프 위치만 다르다.
- Stage는 캡 상단 2px 주얼 램프가 켜지는 INSERT POINT 래칭 스위치다(capture
  키는 입력측이라 함몰 문법을 공유하고, 체결되면 같은 주얼). 두 레인
  캡션(PLAYBACK/RECORDING)과 체인 화살표는 페이스플레이트에 인쇄된 뮤트
  트래킹 각인이다.
- 마스터(All devices/ALL)는 이 기계의 유일한 녹색(accent2) = 버스 전체
  규약으로 켠다. 전원 내린 마스터도 녹색 기억을
  유지한다(`[all*]:checked:disabled` 결합 선택자. 타입 속성과 :checked의
  특이도 동점이 램프를 가리는 함정의 재발을 막는다). 같은 특이도 계층
  안에서는 순간 눌림 규칙을 맨 뒤에 두어, 손가락이 얹힌 캡이 언제나 눌린
  얼굴을 보이게 한다.
- Comment의 물성은 다이모 엠보싱 라벨 테이프다. 각인은 공장 인쇄물이고
  주석은 현장에서 붙인 것이므로, 광택 검정 스트립 + 양각 상아색(#F1E9D8)
  활자로 두 마감 모두에서 검정을 유지한다(LCD와는 활자로 구분한다. LCD는
  녹색 모노 세그먼트다). 사용자 데이터라 대문자 변환을 걸지 않는다.
- 네 에디터 배경은 투명하다(판 위의 직접 페인팅).

### 리스트 chrome: 빈 랙 베이와 서비스 슬롯 (라운드 3)

카드 추가·삽입의 공유 계약(README)에 대한 rack의 답은 랙 자체의 빈자리다.

- 맨 끝 add row는 빈 랙 베이다. 블랭크 패널이 빠진 개구부로 랙 내부가
  들여다보이고, 내부는 두 마감 모두 어둡다(랙 속에는 마감이 없다는 물리적
  정직). 개구부의 챔퍼는 페이스플레이트의 역상(윗변 그림자 = 위 유닛의
  처마, 아랫입술 = 작업등)으로 그리고, 이어 존 자리에는 마운팅 레일과 빈
  볼트 구멍 두 쌍이 유닛의 이어를 기다린다. 베이 안의 스텐실은 휴지 시
  `EMPTY BAY`, 호버 시 `INSTALL MODULE`로 답하며 앰버로 예열된다(각인
  조항. 번역 캡션은 위젯 툴팁이 책임지고 state.label은 쓰지 않는다).
  호버/눌림은 베젤의 앰버 라인이지 버튼 승강이 아니다.
- 첫 경계 삽입선은 서비스 슬롯의 앰버 예열 라인이다. 스트로크만 쓴다(기계
  가공 홈의 그림자 선, 그 위의 앰버 열선, 이어 그루브 위치의 짧은 틱 두
  개). 휴지 시에는 아무것도 그리지 않는다(계약). 원판(disc)이나 채움을
  더하지 않는다. 슬롯이 달아오르는 것이지 부품이 생기는 것이 아니다.

### GraphicEQ 카드: 오실로스코프 표시창 (라운드 3 재작업)

응답 플롯은 GraphicEQPlotWidget의 픽셀 전부를 스킨이 그리는 오실로스코프
표시창이다(`RackChrome::paintGraphicEqPlot`. 불변 규칙 11대로 그리기는
RackChrome에 두고 RackSkin은 얇은 심). 인광 유리 우물이다(표시창 조항).
베젤은 함몰 문법(그늘진 윗변의 처마 그림자 + 점등된 아랫입술)으로 그리고,
포커스는 LCD와 같은 앰버 서비스 엣지로 답한다.

- 그래티큘은 #1F3A31 계열 스코프 그리드로 그린다(다크는 graphGridMinor 토큰
  그대로. 라이트의 그리드 토큰은 패널 도료라 유리에 들어오지 못한다).
  직선은 AA 없는 크리스프 1px로, 메이저는 한 단계 밝게 그린다. 0 dB 축은
  인광 틴트의 중심선 + 스코프 특유의 미세 해시 틱이다.
- 라벨은 유리 여백에 세그먼트 잉크(시트의 LCD 팔레트)로 새긴 숫자
  각인이다(숫자라 미번역). 커서 판독은 유리 안 우상단의 밝은 세그먼트다.
- 곡선은 녹색 인광이다(accent2. 라이트 토큰은 도료라 유리 위에서 발광
  강도로 끌어올린다). 글로우는 넓고 옅은 스트로크를 겹쳐 위조한다(이펙트
  금지). 0 dB 축까지의 옅은 채움이 잔광이고, 빔은 그래티큘 영역 안에만
  산다(관이 트레이스를 가리듯).
- 노드는 발광 조정 도트다. 휴지 = 옅은 돔, 호버 = 예열(돔이 부풀고 밝아짐),
  선택 = 점등 코어 + 조정 칼라 링으로 그리고, 키보드 대상은 표시창이
  포커스를 쥔 동안 앰버 서비스 링을 두른다. 상태 사다리는 휴지<호버<선택이다.
- bandLocked(15/31)에서는 각 노드가 0 dB 축에서 세그먼트 레벨 사다리를
  내린다(하드웨어 분석기의 계단식 컬럼 읽기).
- 비활성은 전원 내린 표시창이다. 그리드·라벨·트레이스가 서비스 농도로
  감광하고 노드는 어두운 돔으로 남지만, 유리와 베젤은 그대로다.
- 정밀 입력은 플롯 아래 판독 스트립이 맡는다. 캡션(#GraphicEQBandCaption,
  \#GraphicEQReadoutLabel)은 대문자 트래킹 각인으로, Freq/Gain 박스는 X1
  LCD 판독창 문법으로, 밴드 레이아웃 캡션은 AR1 R2의 각인
  선택기(paramSelector)로 그린다. 다섯 액션 버튼은 표준 기계 버튼(돌출 캡,
  눌림 시 침강)이다. 플롯·스트립 컨테이너는 판 위 직접 페인팅 법에 따라
  투명하다.

### 분석 그래프: SPECTRUM MONITOR 유닛

분석 독의 응답 그래프는 인광 유리 창(표시창 조항)이 기계 가공 베젤에
안착한 SPECTRUM MONITOR 유닛이다(RackSkin.cpp의
`paintAnalysisMonitor`. 위젯도 타이머도 아닌 상태 없는 페인터). 유리 아래
페이스플레이트 스트립에는 왼쪽에 `SPECTRUM MONITOR` 지정 각인, 중앙에
채널/샘플레이트 캡션(번역된 UI 데이터라 대문자 변환·트래킹 없이 원문 각인),
오른쪽에 `OVER` legend와 PEAK 램프(클리핑 중 점등)를 싣는다.

- 그래티큘과 축은 스코프 그리드 계열의 크리스프 1px(AA off)로 그린다(GEQ
  표시창과 같은 스코프의 법. 크림 마감의 그리드 토큰은 패널 도료라 유리에
  들어오지 못한다). 0 dB 축은 인광 틴트의 중심선 + 미세 해시 틱이고, 축
  숫자는 세그먼트 잉크 각인이며, dB 칼럼은 빽빽해지면 12/24 dB 스텝으로
  솎아 숫자가 충돌하지 않게 한다.
- 빔은 녹색 인광 트레이스다(크림 마감은 발광 강도로 끌어올린 accent2).
  글로우는 겹친 스트로크로 위조하고(이펙트 금지), 축까지의 옅은 채움이
  잔광이며, 빔은 그래티큘 영역 안에만 산다. 진입 호버가 인광을
  예열한다(배경 글로우와 트레이스가 함께 밝아진다).
- OVER 존: 응답이 클립될 수 있는 동안 0 dB 축 위 밴드가 위험 적색으로
  달아오른다. 존의 그래티큘이 적색 경고 괘선으로 바뀌고, 존 안의 dB 숫자도
  적색을 입으며, 빔의 초과 구간은 인광이 낼 수 있는 것보다 뜨겁게 적색으로
  타며 백열 코어가 얹힌다(주석이 아니라 과구동된 빔). 플레이트의 OVER
  램프가 함께 점등한다.
- OVER의 목소리는 패널의 앰버 액센트가 아니라 하드웨어 PEAK 램프의 위험
  적색이다. 과구동은 손상이고, 앰버는 진짜 위험한 것에 쓰기엔 너무 무르다.
  (판례: 분석 그래프 심사)
- 측정 커서는 상하 그랩 틱을 단 스코프 커서 라인으로 내려오고, 빔 위의
  측정점이 밝아지며(초과 구간에서는 적색), 판독은 유리 우상단의 밝은
  세그먼트다.
- 베젤은 함몰 문법 그대로다(유리 상단에 걸리는 처마 그림자 + 유리와
  플레이트 사이의 점등된 아랫입술).

### Device Selector: 패치 베이

장치 선택 다이얼로그는 패치
베이다(`DeviceSelector/skins/RackDeviceSkin.cpp`). APO 버스는 리스트 왼쪽
가장자리 레일 채널 속의 버스 바이고, 장치 행은 1U 베이 스트립이다.

- 토글은 1/4인치 패치 잭이다. 체결하면 플러그가 잭에 앉고 케이블이 버스까지
  패치된다. 호버는 앰버 예열 링 + 버스 쪽에서 다가오는 플러그 고스트로,
  눌림은 플러그가 한 단 깊이 눌린 상태로 그린다.
- 패널 램프가 설치 상태를 말한다. 녹색은 설치되어 유지, 앰버는 변경
  대기(패치 인/아웃), 소등은 손대지 않음이다.
- 섹션은 DZUS 쿼터턴 파스너를 단 마운팅 레일이다(슬롯 수평 = 닫힘, 90도 =
  펼침. `BAY NN` 번호와 PLAY/REC 스탬프는 하드웨어 인쇄). DEFAULT/EXP는
  와이어프레임 스탬프로, 사용 불가 베이는 전원 내린 유닛으로, 선택은 앰버
  서비스 베젤로 그린다.
- 다이얼로그 버튼은 기계 가공 캡(주 버튼은 앰버 백라이트 legend)이고,
  트러블슈팅 디스클로저는 T-핸들 래치를 쿼터턴으로 여는 서비스 해치다.

### 맨텍스트 행: AUX 유닛의 프로그래밍 LCD (라운드 3)

해석되지 않는 줄(맨 노트, `If` 같은 프로그래밍 명령)은 AUX 유닛이고, 원문은
프로그래밍 LCD에 as-written으로 태운다(표시창 조항, 녹색 모노 세그먼트).
행 위젯이 토큰 인라인 스타일을 깔아 QSS로는 못
이기므로 `prepareCommandRow`가 `FilterCardRawText`에 직접 입힌다. 전원 내린
유닛은 세그먼트가 감광한다. `>_` 프롬프트 글리프는 기본(뮤트 모노 잉크)을
그대로 쓴다(이미 패널 인쇄로 읽히므로 더 얹지 않는다).

### 동적 명령어: 릴레이 전원 버스 (If/Eval)

공유 계약: If 블록의 스코프 표시는 `ISkin::paintScopeGutter`(카드 왼쪽
들여쓰기 여백. false를 돌려주면 공유 채널 레일이 남는다)가 맡고,
ElseIf/Else/EndIf 행은 `logicSiblingsIndentAsMembers = true`로 멤버
깊이(의미 깊이 + 1)에 장착해 레인이 그 전폭 얼굴들 뒤에서 죽지 않고
통과하게 한다. (판례: A/B 목업 라운드, 이슈 #179)
`branchState`/`lineSkipped`/`evalText`는 엔진의 마지막 로드가 남긴 참고용
사실(ConfigLoadTrace)이라 편집과 다음 분석 사이에 낡으므로, 페인트 시점에만
읽고 구성 시점에 굽지 않는다.

rack의 답은 거터의 릴레이 전원 버스다(그리기는 불변 규칙 11대로
RackChrome). (판례: 동적 명령어 라운드, 게이트 이슈 #179 판정 A)

- 버스는 랙 개구부의 어두운 솔기 케이싱에 앰버 코어를 물린 급전선이다. If
  헤드 유닛의 아래 여백에서 짧은 급전점(장착 솔기에 앉은 작은 주얼 램프가
  조건을 보고한다)으로 태어나 멤버 행들을 지나 EndIf의 접점 블록에서
  끝난다. ElseIf/Else는 버스 위의 금속 접점 블록 + 카드로 향하는 탭
  스텁으로, 멤버 행은 탭 스텁 끝의 파일럿 램프로 그린다.
- 분기 판정은 paintLed 문법의 램프가 말한다. 택한 분기는 녹색 점등, 평가
  오류만 적색 서비스 램프이고, 거짓·단락(체인 기충족)·미분석은 전부 같은
  꺼진 돔이다. 램프는 켜지거나 꺼질 뿐, 하드웨어는 제3의 주장을 하지
  않는다.
- 거짓 분기가 삼킨 줄은 자기 구간만 감전 해제한다(코어가 카드 색으로 물러난
  앰버 딤. 바깥 레인은 아래 행들을 위해 살아 있다). If 레인 밖의 채널 그룹
  레벨은 뮤트 점선 레일로 물러나 Channel×If 중첩이 읽히게 한다.
- Eval 행의 본문은 맨텍스트 행과 같은 AUX 프로그래밍 LCD를 탄다. 계산값은
  표시창의 일이지 램프의 일이 아니다.

### 업데이트 토스트: 서비스 노티스 (라운드 3)

위젯이 토큰 카드(면 + 헤어라인 보더 + 앰버 뉴스 킬)를 직접 그리므로 rack은
잉크만 답한다. 메시지는 따뜻한 본문 잉크의 문장이다(번역된 UI 데이터라
각인이 아니므로 대문자·트래킹 금지). 닫기 캡은 작은 기계 버튼으로, 호버에서
앰버로 덥혀지고 눌리면 침강한다. LCD로 만들지 않는다. 알림은 판독값이
아니라 서비스 태그다.

### 필터 픽커: 1U 모듈 프리셋 브라우저

- 브러시드 페이스플레이트로 그린다(세로 광택 + 가로 브러싱 라인, 기계
  가공된 1px 엣지와 점등된 상단 베젤). 네 귀퉁이의 일자 나사(슬롯 각도
  제각각), `MODULE SELECT` 각인 헤더 + 녹색 전원 LED, 하단 레일의
  `EAPO-XT SERIES` 모델 각인을 단다.
- 검색창은 함몰된 LCD 문자 표시창이다(표시창 조항, 녹색 모노 세그먼트).
- 카테고리는 리벳 박힌 각인 섹션 플레이트로, 항목은 베젤 달린 패널 LED가
  붙은 라벨 슬롯으로 그린다.
- 램프 감광의 법: 비점등 슬롯 램프는 한 단계 물러난다(옅은 베젤 잉크,
  반투명 돔, 희미한 스펙큘러). 슬롯 기둥이 불릿 나열로 읽히지 않도록 시선은
  점등(선택)과 예열(호버) 램프만 끈다. (판례: AR1 R5)
- 갤러리 쇼케이스: hover는 두 번째 슬롯의 램프 예열(선택 슬롯의 점등과 한
  장에 대비)로, 빈 검색은 LCD의 죽은 검색어 + 플레이트의 `NO SIGNAL`
  각인으로 보인다.
- 모든 chrome은 RackChrome의 그리기 문법을 재현해 카드 페이스플레이트와
  시각적으로 연속이다.

## 하지 말 것

- 이미지/비트맵 에셋을 도입하지 않는다. 전부 그린다.
- 평면(flat) 디자인 어휘를 혼입하지 않는다(채운 색 배지, 그림자 없는 순수
  플랫 카드, 형광 액센트). 이 스킨에서 색은 램프와 각인에만 산다.
- 디스플레이(LCD/판독창)를 패널 마감에 맞추지 않는다. 표시창은 언제나
  어두운 우물이다.
- 페이스플레이트에 raw 설정 원문을 인쇄하지 않는다.
- 각인 문구에 tr()을 적용하지 않는다(하드웨어 인쇄물이다). 단, 진짜 입력
  요소의 placeholder는 번역한다.
- 이어 존에 콘텐츠를 배치하지 않는다(나사·LED와 충돌한다).
- 차가운 흰색/회색 텍스트를 쓰지 않는다. 이 스킨의 잉크는 따뜻하다.
- 램프를 맨 발광 원반으로 그리지 않는다. 모든 램프는 paintLed 문법(베젤 +
  돔 + 스펙큘러)을 거친다. 다크 마감에서 맨 원반은 부품이 아니라 도료로
  읽힌다. (판례: 동적 명령어 라운드)

## 이웃 스킨과의 경계

soft도 깊이를 다루지만, soft의 고도는 명도 스텝의 추상이고 rack의 깊이는
부품의 물리다(나사·베젤·함몰 우물). matrix도 점등 어휘를 쓰지만, matrix의
LED는 보드 위의 추상 신호(셀의 점등)이고 rack의 LED는 베젤에 박힌 물리
부품이다. rack에서 격자 좌표나 모노 코드 셀이 보이면 matrix를 침범한 것이다.

### VST 채널 채우기 레일 (SlotFill)

강제 협상 슬롯의 채널 배선. 모듈 페이스에 파인 **패치 스트립**(위는 어둡고
아래는 밝은 각인 순서의 함몰 밴드) 안에, 각인 역할 토큰과 셀이 늘어선다.
셀과 접기 래치는 **버스 IN/OUT 선택기와 같은 캡 부조** 하나로 통일된다.
잔잔한 래치다운 캡, 메뉴 열림·펼침=눌림, 호버·포커스=앰버 데움, 선택 밖
채널=danger 테두리와 인쇄, `-`와 암묵 기본값=muted 인쇄. IN/OUT과의
구분은 기제가 아니라 위치(레일)·슬롯별 각인·인쇄된 채널값이 맡는다.

접기 래치는 같은 캡에 파일럿 LED(paintLed)와 각인 FILL만 얹은 단순형이다.
상태는 램프가 말하고 캡은 눌림 어포던스만 준다. 올라옴=접힘, 눌림=펼침.

접기 래치는 세그먼트 뱅크의 캡 구성을 통째로 물려받은 **기계 가공 키**다.
자기 함몰 마운트 속에서 금속 그라데이션과 그레인을 입고, 래치다운 시
베벨이 반전되며 눌린 면에 앰버 램프 열기가 닿는다. 파일럿은 이 스킨이
가진 유일한 램프(paintLed)를 베젤에 앉힌 것이고, FILL 레전드는 캡 상태를
따라 각인된다. 올라옴=접힘, 눌림=펼침으로 이 기기의 모든 스위치와 같은
방향으로 래치된다.
