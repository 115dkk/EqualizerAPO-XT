# Signal Matrix (`matrix`) — 디자인 헌법

> **공항 출발 안내판 / 방송국 라우팅 매트릭스.** 모든 것이 격자에 정렬되고,
> 모든 행은 좌표를 가진 셀이며, 색은 상태에만 허락된다.

## 철학

Signal Matrix는 "화면은 보드(board)다"라는 단일한 은유로 움직인다. 사용자는
메뉴를 '탐색'하는 것이 아니라 계기판을 '조작'한다 — 행을 고르는 것은 버스를
선택하는 것이고, 항목을 고르는 것은 **크로스포인트를 체결(engage)하는
것**이다. 픽커 라운드의 차별화 기준이 정확히 이 문장이었다: "메뉴를 둘러보는
게 아니라 크로스포인트를 거는 것처럼 보여야 한다."

이 스킨의 가장 단단한 헌법 조항은 **색의 배급제**다. 신호등 색(녹/앰버/적)은
상태 전용으로 예약되어 장식에 쓸 수 없고, 액센트(시안)는 체결·선택 상태
전용이다. 그 결과 카탈로그 자체는 단색이다 — 타입 배지조차 명령별 색을
버리고 모노 글리프(`typeBadgeStyle`/`typeBadgeInk` 오버라이드가 typeColor
인자를 의도적으로 무시한다; 피드백 라운드 2부터 내용물은 코드 텍스트 대신
픽커의 픽토그램이되 잉크는 여전히 보드 잉크 단색이다)로 그린다. 다섯 스킨 중
색이 정보 채널로서 가장 엄격하게 보존되는 스킨이고, 그래서 램프 하나가
켜지는 순간이 가장 크게 읽힌다.

두 번째 조항은 **격자**다. `MatrixMetrics::gridPitch = 24`(12px 두 줄)가 보드
전체의 모눈이고, 카드 본문 뒤에 흐린 세로 모눈선("보드가 앉아 있는 모눈종이",
α 60/비활성 30)이 실제로 그려진다. 행 높이 36, 채널 들여쓰기 24 — 전부 이
피치의 배수다. 정렬은 미덕이 아니라 규칙이다.

## 불변 규칙

1. **색 배급제.** 녹(success)=가동, 앰버(warning)=바이패스, 적(danger)=음수/
   위험. 이 셋은 상태 외 사용 금지. 액센트 시안(#22D3EE/#008EAA)은 체결·선택·
   호버 밴드 전용. accent2(#7CFFB2/#0A8F57)는 바이폴라 컷 방향 전용. 카탈로그
   ·라벨·배지는 단색. (조항별 의미는 아래 '색 의미론' 절이 명문이다.)
2. **라운드 0 + 1px 룰.** 직각 셀과 1px 괘선만. 곡률·그림자·글로우 금지.
3. **모든 것은 격자 위에.** gridPitch 24의 배수로 치수를 정한다. 모눈 텍스처는
   장식이 아니라 보드의 정체성이므로 지우지 않는다. 단, 행 본문(파라미터
   영역)은 불투명 에디터 패널이 모눈을 덮는다 — AR1 라운드에서 본문 관통을
   시도했으나 메인테이너 심사에서 거슬리는 잔상으로 판정되어 되돌렸다(이슈
   #93). 모눈은 보드 표면(카드 사이·헤더 주변)까지만 보드의 정체성이다.
4. **행 = 좌표를 가진 셀.** 왼쪽 3px 상태 레일(`cardRailWidth = 3`), 왼쪽
   거터의 5px 상태 램프(실선 녹=가동, 테두리만 앰버=바이패스), 좌표 칼럼 밴드
   (`coordinateBandWidth = 120`). 행 번호 셀은 픽커와 같은 좌표 문법을
   쓴다: 타입의 버스 문자 + 줄 번호("B3" = 3행의 BiQuad). 문자는 지정이지
   식별자가 아니며(두 타입이 한 문자를 나눠 쓸 수 있다), 유일성은 줄
   번호가 책임진다. 좌표 잉크는 픽커의 좌표 셀과 같이 평시 muted,
   체결(선택) 시에만 액센트다.
5. **수치는 모노 + 박스 셀.** 권위 있는 판독값은 언제나 "박스 안의 모노
   숫자"다(노브 아래 셀, 값 스크럽 셀, 픽커 푸터의 보드 라인). 값 셀은
   네이티브 스핀 버튼 없이(X1) 함몰 배경 + 1px 룰 + 굵은 모노 잉크의
   정사각(라운드 0) 셀로 그린다. 호버는 룰 예고, 포커스/입력은 액센트 체결,
   비활성은 점선 취소다(M4).

## 색 의미론 (M3 명문)

신호등과 액센트의 의미는 보드 전체에서 단 하나다. 아래 표가 법이고,
구현이 표와 다르면 구현이 틀린 것이다.

| 색 | 의미 | 구현 위치 |
|---|---|---|
| 녹(success) | 가동/저장됨 | 행 레일·상태 램프(가동), 툴바 상태 램프(저장됨), Copy 유니티 셀("1") |
| 앰버(warning) | 바이패스/수정됨/주의 | 행 레일·속 빈 램프(바이패스), 툴바 램프(수정됨), 포맷 배지(비네이티브 스트림) |
| 적(danger) | 음수/위험/파괴적 동작 | Copy 음수 계수("INV"), Include 오류 판독, 닫기 셀 프리라이트 |
| 액센트 시안 | 체결·선택·호버 예고 | 체결 셀 LED, 선택 룰, 크로스포인트 밴드, 패치 트레이스, 스캔 캐럿 |
| accent2 녹청 | 바이폴라 컷 방향 | gain 노브의 좌측(컷) 세그먼트·포인터 |

이 다섯 줄 밖의 색 사용은 전부 장식이며 금지다. 비활성(결항)은 색이 아니라
형태(점선 룰, 속 빈 램프, 취소선, 저알파)로 말한다.
6. **크로스포인트 호버.** 호버는 행 밴드 + 좌표 칼럼 밴드를 동시에 켜고, 둘의
   교차부가 가장 밝다(α 22/14/26). 점이 아니라 교차로 읽힌다.
7. **크리스프 1px.** 셀·괘선·모눈을 그릴 때 안티에일리어싱을 끈다. 흐릿한
   1px 선은 이 스킨에서 버그다.

## 빛과 상태의 문법

- **hover** — 크로스포인트 예고: 행 밴드 + 좌표 칼럼 밴드 + 교차부. 보드
  전체를 가로지르는 칼럼 밴드는 현재 카드 안에서만 그릴 수 있다는 한계가
  알려져 있다(FilterTable 수준 훅이 wish 목록에 있다).
- **selected/engaged** — 셀이 체결된다: 액센트 LED 채움 + 1px 액센트 룰.
  픽커의 활성 버스는 3px 체결 밴드를 받는다.
- **focused** — 정사각 셀 브래킷(글로우 아님 — "이 스킨의 모서리 언어는
  직사각형이다").
- **disabled** — **결항 처리된 출발편**: 점선 외곽 룰 + 속이 빈 앰버 램프 +
  (요약에) 취소선. 행은 보드에 남는다 — 안내판에서 결항 편이 사라지지 않듯이.
- **dragging** — 점등 색이 lighter(130), 호버는 lighter(115).

## 타이포그래피

라벨은 DM Sans, 수치·코드·좌표는 DM Mono. 위계는 **격자 위치와 균일한
활자**가 만든다 — 크기 변화로 위계를 만들지 않는다(보드의 모든 행은 같은
활자를 쓴다). 타입 코드는 BQUAD/INC/VST 같은 모노 약호다.

## 구성 요소별 표현

### 노브 — LED 링 로터리 인코더 (Annex K)

값이 **이산적인 점등 세그먼트**로 읽힌다.

- 바이폴라는 세그먼트 14개(짝수 → 12시에 자연스러운 중앙 갭), 유니폴라는
  15개(홀수 → 중앙 포함 모든 위치에 세그먼트). 갭/틱의 존재만으로 두 종류가
  갈린다.
- 바이폴라는 중앙 갭에서 좌(컷=accent2)/우(부스트=accent)로 점등, 유니폴라는
  최소점부터 시계방향 채움. **0 dB 디텐트는 "갭만 남은 상태"다**: 점등
  세그먼트 0개 + 갭 + 디텐트 틱이 그 자체로 증거가 되어야 한다(X3,
  갤러리의 gain0db 행).
- **비점등 링은 항상 보인다(M1).** muted 잉크 저알파(가동 80/비활성 40)의
  고스트 링이 270도 범위 기하와 중앙 갭을 상시 노출한다. 보더 잉크는 라이트
  카드에서 소실되므로 쓰지 않는다.
- **점등 셀은 고스트 셀보다 굵고 밝다(M1).** 점등 3.5px/비점등 2.5px,
  다크 보드에서는 점등 색에 lighter(112)의 백색 헤드룸을 더한다(라이트
  토큰은 흰 바탕 대비가 이미 최대라 그대로). 호버/드래그는 그 위의 단계다.
- 바이폴라 디텐트 틱은 갭 바깥의 1px 본문 잉크(text) 선이다 — 0 dB에서
  갭과 틱이 디텐트 선언의 전부이므로 muted로 그리지 않는다.
- 몸통은 평평한 인코더 + 포인터 선. 비활성은 점선 보더의 빈 몸통.
- 정확한 값은 노브 아래 **박스 모노 셀**(`knobCellHeight = 16`,
  surfaceSunken 배경, 드래그 중 액센트 보더)이 권위를 가진다. LED 링은
  어림값, 셀이 판독값이다.

### 카드(행) chrome

QSS는 직각 셀 + 1px 룰 + 3px 신호등 레일(녹=가동, 앰버=바이패스; 비활성은
외곽 룰이 점선으로). 그 위에 paintCardChrome이 헤더 밴드 채움, 헤더/본문
사이 1px 룰, 모눈 텍스처, 상태 램프, 크로스포인트 호버를 그린다. 헤더 위젯은
투명이다(밴드는 페인터 소유).

AR1 M2로 픽커의 좌표 언어가 행에 수입됐다.

- **본문 모눈 관통은 기각.** 카드 에디터를 투명화해 모눈을 파라미터 영역에
  관통시키는 시도는 메인테이너 심사에서 잔상으로 판정되어 되돌렸다(이슈
  #93). 에디터 본문은 불투명 패널로 남는다. paintCardChrome의 모눈 잉크
  모드별 보정(다크 80/라이트 90, 비활성은 절반)은 보드 표면용으로 유지.
- **행 번호 = 버스 좌표.** MatrixSkin이 prepareCommandRow에서 번호 셀
  텍스트를 "버스 문자+줄 번호"로 다시 쓴다(불변 규칙 4).
- **캡션 스트립.** 카드 맨 아래에 픽커 푸터 문법의 함몰 보드 라인
  (`MatrixRowCaption`, 높이 18)이 붙어 행의 원문 스펙("> Filter 1: ON PK
  ...")과 좌표를 판독한다. 평시 muted로 대기하고, 행 크로스포인트 호버 시
  마커·좌표가 액센트로, 스펙이 본문 잉크로 점등한다 — 호버가 행 스펙을
  에코한다. 공용 raw 미리보기 스트립은 이 스킨에서 캡션 스트립이 대체한다
  (`showRawPreview = false`). 비활성 행은 원문에 "#"가 그대로 보이는
  취소 라인이다.

### 타입 표시 — 단색 코드 셀

타입은 색이 아니라 **모노 코드 텍스트**가 말한다. typeBadgeStyle 오버라이드가
타입 색을 버리고 텍스트 잉크 + 보더만 남긴다. 색 배급제의 직접 적용이다.

### 값 셀과 선택기 (X1/X5/M4)

- **값 셀**(`valueScrub` 동적 프로퍼티): 스핀 버튼 없는 정사각 보드 셀.
  함몰 배경 + 1px 룰 + 굵은 모노 9pt. 스크럽/휠/타이핑으로 조작하고, 호버는
  룰 예고, 포커스는 액센트 체결, 비활성은 점선 취소.
- **파라미터 모드 선택기**(`paramSelector`): 라벨로 오독되던 셀의 정직화.
  muted 대문자 캡션 잉크의 투명 셀이되, 1px 룰의 드롭다운 존과 화살은
  유지한다(선택기임이 보여야 한다). 호버 프리라이트, 열림은 액센트 체결.
  모드가 하나뿐이라 비활성인 선택기는 점선 룰의 취소 셀이다 — 선택지가
  아닌 것을 살아 있는 셀로 위장하지 않는다.
- **gain 캡션**: gain에는 모드가 없으므로 정직하게 라벨이다. 캡션 계급의
  잉크·크기만 공유하고 셀 룰과 화살은 받지 않는다.
- **템플릿 선택기**(`filterSelector`): 행이 물고 있는 항목의 판독 셀.
  툴바의 목적지 판독 셀과 같은 함몰 배경.

### 참조 카드 — 보드의 피드 라인 (AR2)

Include/Convolution/MultiConvolution/VST 행의 본문은 `MatrixReferenceCardView`가
세우는 피드 라인이다: 함몰 모노 **마커 셀**(`> SRC`/`> IR`/`> IR+`, kind에
묶인 불변 약호) + `<dir>@` 위치 판독(muted, 페이로드 앞 — 읽는 순서대로
장소가 먼저 오고, at 기호가 버스 주소처럼 장소를 닫는다; 재작업 라운드) +
페이로드 이름(가장 밝은 모노 잉크). IR 판독값은 **박스 함몰 모노 셀**(불변 규칙 5 — `100.0 ms`
`4800 samples` `48000 Hz` `2 ch` 각각 한 셀)이고, 멀티컨볼루션의 출력 채널
콤보도 함몰 좌표 셀로 어순(`<channel> <file>`)에 끼어든다. VST는 본문
머리의 `> IN … EXTERNAL DEVICE … OUT >` 포트 스트립(muted 단색 가구) +
단색 `VST2`/`VST3` 코드 셀. 결손은 배급표의 명문대로 danger다: 마커 셀이
속 빈 danger `MISSING`(빈 참조는 `NO FEED`)으로 전환하고, `LOCATE` 모노
캡스 셀이 복구 진입점이 된다(평시 단색, 호버에만 액센트 예고). ABS는 속
빈 앰버 토큰(주의 고지), 상태줄은 `! ` 마커의 모노 보드 리마크 한 줄이다.
화살은 전부 ASCII `>` — DM Mono에 U+25B8이 없어 오프스크린에서 두부가
되는 함정을 피한 결정.

### Copy 라우팅 — 크로스포인트 격자 (Crosspoint)

이 스킨의 본진. 입력 채널 = 열, 출력 채널 = 행의 평면 격자이고 각 셀이
라우팅 계수를 색+숫자로 부호화한다: 유니티 = 녹색 "1", 음수 = 적색
"INV"/값, 그 외 = 액센트 + 값. 가상 채널은 점선 알약 헤더다. 클릭 = 유니티
토글, 더블클릭 = 셀 값 편집(빈 값 = 제거). 장치 채널 전체가 항상 격자에
깔려 있어(시딩) 비운 Copy도 GUI로 재구성할 수 있다. "입력 X가 출력 Y로
어떤 게인으로 가는가"라는 조회에 최적화된, 다채널(7.1+가상)에서 가장 강한
표현이다.

MultiConvolution 카드가 같은 격자를 고정 소스 모드(RoutingPortModel)로
재사용한다: 열이 IR 파일의 채널 번호("0".."N-1", 항구이므로 점선 없는 알약)로
고정되고, 팩터가 없어 체결 셀은 계수 대신 녹색 접점 도트(●)를 찍는다. 클릭
토글만 남고 더블클릭 편집은 꺼진다.

### 장치·채널·주석·스테이지 카드 (Phase 2)

네 카드는 보드의 네 **계급**이다. 같은 체결 문법(체결 = 액센트 채움 + 1px
룰, 호버 = 프리라이트, 비활성 = 점선 룰 + 죽은 잉크의 결항 처리)을
공유하되 셀의 재질과 활자로 가른다. Device = 함몰 목적지 셀(@GRAPH@ + 1px
룰, 산세리프 — 장치 이름은 이름이지 값이 아니다; 미설치 = 결항 편; reveal
토글은 투명 모노 캡션 셀로 강등). Channel = 좌표 셀(DM Mono 700 + 자간,
24px 정사각 좌석; 가상 채널은 점선 유지 + 체결 시 액센트 잉크). Stage =
투명 기능 셀(대문자 캡션, InstantMode engage 문법; 미지 토큰은 ABS 셀
선례의 속 빈 앰버 토큰 = 배급표 안의 주의 지출; 두 레인
캡션(PLAYBACK/RECORDING)은 툴바 캡션 문법의 보드 섹션 표제). Comment =
보드의 **리마크 라인**: 결항 편이 아니므로 취소선을 걸지 않고
(`filterKind="#"` 해제), 레일은 무신호의 border 잉크 3px 실선, 상태 램프는
생략한다(리마크에는 신호 상태가 없다 — 크롬의 remark 분기). 게시물은 이
보드에서 반드시 **셀**에 산다: '#' 마커는 침강 지정 셀, 본문은 침강 라인
셀(@GRAPH@ 데이터 셀 그라운드 + 1px 룰)에 담긴다 — studio의 무크롬 인쇄
라인과 갈라서는 지점. 호버 = 체결 깊이 프리뷰, 포커스 = 액센트 룰 + 스캔
스트립 채움. 네 에디터 배경은 투명(칩 밑 @BG@ 패치 금지).

### 필터 픽커 — 2축 크로스포인트 계기

- 왼쪽 **버스 레일**: 카테고리마다 박스 문자 지정(A..G) + 항목 수 판독.
- 오른쪽 **좌표 셀 칼럼**: 항목마다 불변 모노 보드 좌표(C1..C8). 필터링해도
  좌표는 재부여되지 않는다.
- 체결 셀 = 액센트 LED 채움 + 1px 룰, 활성 버스 = 3px 체결 밴드, 그리고
  **2px 패치 트레이스**가 버스 셀과 커서 셀을 칼럼 구분선 너머로 잇는다 —
  "라우팅을 문자 그대로 보이게" 만든 선이다.
- 검색은 헤더의 **함몰 스캔 판독 스트립**(`> _` 캐럿, 입력 중 액센트 보더).
  둥근 검색창은 이 스킨에 존재하지 않는다.
- 푸터는 출발 안내판의 한 줄: 체결된 좌표가 삽입할 설정 줄 원문 + 좌표.
- 카탈로그는 단색, 액센트는 체결 상태에만 — 색 배급제의 픽커 적용.
- 호버 프리라이트는 체결 채움보다 확실히 약하되 주소 지정으로 읽힐 만큼
  진하다(엔트리·버스 40, 체결은 48~56 — M2 재보정. M1의 16~18은 렌더 실측
  약 3.5% 밝기 차로 지각 임계 아래였고, 사용자에게 '호버가 하이라이트를
  안 한다'로 보고된 결함이었다. 체결은 채움 외에 액센트 룰·3px 밴드·패치
  트레이스를 더 가지므로 사다리는 유지된다).
- **빈 스캔은 보드를 비우지 않는다.** 응답하는 항목이 없으면 엔트리 칼럼에
  `-- NO SIGNAL --` 보드 표기를 게시하고 푸터는 `> NO MATCH`를 판독한다.
  출발 안내판은 꺼지는 대신 결손을 게시한다.

## 하지 말 것

- 신호등 색·액센트를 장식이나 타입 식별에 쓰기. 색 배급제가 1조다.
- 곡률, 그림자, 글로우, 그라데이션 장식. (모서리 언어는 직사각형이다)
- 모눈 텍스처 제거나 비-배수 치수 도입.
- 타입 배지에 색 입히기(단색 코드 셀이 정답이다).
- 안티에일리어싱 켠 채 1px 괘선 그리기.
- 좌표·번호를 필터링/정렬에 따라 재부여하기. 좌표는 불변이다.
- 비활성 행을 숨기거나 흐리게 뭉개기. 결항 편은 보드에 점선으로 남는다.

## 이웃 스킨과의 경계

가장 가까운 이웃은 **minimal**(둘 다 모노, 1px, 라운드 0)이다. 경계: minimal은
문서/터미널(텍스트 줄, 줄무늬, 무채색, 상태=잉크 농도), matrix는 계기판(모눈
텍스처, 좌표, 신호등 색, LED, 상태=점등). matrix가 좌표와 램프를 잃으면
minimal로 퇴화하고, minimal이 상태색과 격자를 얻으면 matrix를 침범한다.
점등 어휘는 **rack**과도 닿지만, rack의 LED는 베젤에 박힌 물리 부품이고
matrix의 LED는 보드 셀의 추상 점등이다(스큐어모피즘 금지).
